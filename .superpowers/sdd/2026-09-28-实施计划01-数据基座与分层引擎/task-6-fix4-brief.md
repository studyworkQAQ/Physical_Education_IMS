## 1. 背景：关切 ② 为什么被驳回（必读，否则你会重复同一个错误）

上一轮实现者上报：「复审的窗口/池/校正计数在字节完全相同的数据上不可复现」，并给出自己的一组数字（稳定可行 493、零宽 145、零宽且标为稳定 91、波动大可行 257、持续下滑 215、稳步提升 486、`triggered = 16`）。

**控制者用独立探针在同一个 HEAD（`945877f`）上重测，方法与「直接读生产代码自己构造的 bundle」完全一致**（monkeypatch `_trend_labels` 与 `_trend_prev_targets` 各包一层 spy，spy 只做记录、原样转发同样的 `population/cfg/rng/bundle`，**不额外消耗随机数**），实测：

| 量 | 复审（在 `bed07ed`） | 控制者（在 `945877f`） | fix round 3 实现者 |
|---|---|---|---|
| 校正 `triggered` / `max_rounds` | 19 / 1 | **19 / 1** | 16 / 1 |
| 稳定类可行 | 489 | **489** | 493 |
| 其中零宽窗口 | 133 | **133** | 145 |
| 零宽**且**实际标为「稳定」 | — | **88** | 91 |
| 波动大 / 持续下滑 / 稳步提升 全量可行 | 260 / 203 / 487 | **260 / 203 / 487** | 257 / 215 / 486 |
| `bundle.curr` 与记录 `score_*` 不符处 | — | **0 / 3000** | 0 / 3000 |

两轮独立测量在**不同 commit 上**（`bed07ed` 与 `945877f` 之间 `fitness.py` 只改了注释，`generate.py` 只改了一行判据，生成逻辑 0 行改动 → bundle 必然逐字相同）得到**完全一致**的结果；第三轮实现者的数字与两者都不符。

**根因（控制者的判断）**：上一轮实现者自述用了三条路径，其中两条是**重新推导**而非读生产状态——「用记录的 `score_*` 列重算 `magnitude`」与「直接调 `_delta_target_windows`」。这两条都需要自己提供 `bmi_delta`，而 `bmi_delta` 一旦取法不同（例如从记录反推而不是用 bundle 里的 `curr_bmi - prev_bmi`），`b` 就变，窗口全变。**他们自己的关切 ⑥ 已经指出「`持续下滑` 的窗宽对 `b` 最敏感」，而 `持续下滑` 恰好是差得最多的一项（215 vs 203）——线索就在手里，结论却下反了。**

**这条教训写进账本，也写给你**：

> **当两次测量在字节相同的数据上不一致时，读生产代码自己的中间状态的那一次胜出，重新推导输入再调函数的那一次不算证据。** 后者测的是「我对这段代码的理解」，不是「这段代码做了什么」。

**所以本轮的第一件事，是把被写进源码注释的那组错数字改回来。**

### 2.2 AST 守卫补两种别名写法（必修，上一轮关切 ① 已授权）

上一轮实现者上报了守卫剩余的两个侧门，并**正确地没有自作主张扩大匹配规则**（因为最省事的堵法会误伤一个恰好叫 `random` 的合法局部变量）。控制者**授权**按它建议的做法实现：**在已有的预扫阶段加一张别名表**。

要堵的两种写法（上一轮探针实测 MISSED）：
- `import numpy.random as npr` + `npr.normal(...)`
- `from numpy import random` + `random.normal(...)`

（第三种 `from numpy.random import normal as n` + `n(...)` 目前只在 import 行 CAUGHT、调用点不报——**这一条也一并堵上**，别名表天然覆盖它。）

**要求**：
- 别名表在**同一趟 AST 遍历里先收集、后判定**，或分两趟（先收集 import 别名，再扫调用点）。要覆盖的映射至少包括：`numpy.random` / `np.random` 被 `as` 成的名字、`from numpy import random [as X]` 里的 `random`/`X`、`from numpy.random import <fn> [as Y]` 里的 `<fn>`/`Y`。
- **必须避免误伤**：一个恰好叫 `random` 的**局部变量**（例如 `random = np.random.default_rng(0)`，随后 `random.normal(...)` 是完全合法的根生成器用法）不得被判违规。所以别名表只能由 **import 语句**填充，不能由「名字看起来像」填充；且 `default_rng(...)` 的赋值目标要显式排除。请把这条写进 docstring，并**用测试双向钉住**（`random = np.random.default_rng(0)` + `random.normal(...)` 必须零违规）。
- **自证测试**：三种别名写法各至少一条参数化用例（形式与现有 42 条一致：违规源码写进 `tmp_path` 假模块，断言 `_offenders_in` 返回违规）；负对照至少两条（上面那个合法局部变量 `random`；以及 `from numpy.random import Generator` 只作类型标注仍放行——上一轮已有这条，别弄坏）。
- 收尾必须仍满足：`_scan(app/seed) == []`，且从 `app/seed` 现挖的合法 `rng.*` 调用点集合仍零违规。
