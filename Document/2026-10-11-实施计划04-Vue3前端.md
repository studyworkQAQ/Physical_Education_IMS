## 0. 目标与非目标

**目标**：把 Plan 01–03 建好的后端**接上电** —— 一个学生能在手机上完成「看训练单 → 打卡 → 交课堂快评」，一个教师能在大屏上看到「分层分布 → 预警队列 → 处置 → 班级周报」，一个管理员能对 23 个资源做增删改查。**判据是「起两个服务、点着走完一条业务链」，不是「页面数量」。**

**非目标（一律不做，理由都是用户裁定或 spec 原文）**
- ❌ 真实登录/鉴权。身份走两个请求头（`X-Student-Id` / `X-Teacher-Staff-No`），前端做一个**身份切换器**代替登录页。spec §9 与 `deps.py:3-7` 逐字：「挡事故、不挡攻击」。
- ❌ 真实推送。`InAppChannel` 只做站内消息（spec §8.3 原文「原型不做」）。
- ❌ 真实乐跑/第三方对接。
- ❌ 单元测试全覆盖 / E2E 自动化框架。**前端只做 Task 5 的「真实联调脚本」**（起两个服务、用真 HTTP 走完一条链、把每一步的请求与响应原文打出来）。理由：用户要的是「能运行起来的原型」，而前端逻辑的正确性今天由**后端 1255 条测试**兜着；前端自己的风险全在「对接」上，故把预算花在对接验证上。
- ❌ i18n、暗色主题切换、响应式断点的全矩阵。**只做两档**：学生端按 375px 宽设计（手机）、教师端按 1440px 宽设计（大屏）。

## 1. ⚠️ Global Constraints（对齐约束 —— 本计划最重要的一节）

**这 22 条全部是控制者从 Plan 03 的账本、终审报告与两波 fix 里逐条捞出来的实测事实。每一条都对应一个「前端会静默做错」的失效形态。**

### A. 身份与 CORS

1. **身份只能走请求头，不能用 cookie / `credentials: 'include'`。** 后端 CORS 实测是 `allow_origins=["*"]` + `allow_methods/headers=["*"]`、**不带** `allow_credentials`（`app/main.py:184-189`）。浏览器规范禁止 `*` 与 `credentials` 并存 → 一旦前端设 `withCredentials`，**所有跨域请求会当场失败**。
2. **两个头**：`X-Student-Id`（学生侧）、`X-Teacher-Staff-No`（教师侧）。**它们是 OpenAPI 的 `apiKey` securityScheme**，故 `/docs` 上有 Authorize 按钮、且 `openapi-typescript` / `orval` 能生成出带身份参数的客户端。
3. **92 个操作里 45 个挂 `security`**：**26 个是泛型 CRUD 的写入侧**（9 个可写资源 × POST/PATCH，其中 `semesters` 是 `on_delete='forbid'` 故没有 DELETE → 8 个 DELETE）+ **19 个特例端点**。**47 个 GET 全部匿名**（大屏与列表要能匿名读）。⚠️ **故：所有写请求必须带教师头，所有读请求可以不带。**
4. **缺头是 401 `unauthenticated`，工号/学号不在册是 401 `unknown_teacher` / `unknown_student`，越权是 403 `forbidden`。** ⚠️ **422 是 Pydantic 的校验失败，不是身份问题** —— 若前端看到 422 且 `loc` 里是 `["path", "xxx_id"]`，那**几乎一定是路由顺序或路径拼错**，不是数据问题（终审专门点过这一档：那个报错会把下一个人支去修前端）。

### B. 契约与类型

5. **⚠️ 92 个操作里有 24 个的响应 schema 是 `{"type":"object","additionalProperties":true}`** —— 即 **23 个泛型 list 端点 + `/api/health`**（Task 1 实测坐实：产物里 `[key: string]: unknown;` 出现 **42** 次 = 24 次在 `operations` 内 + 18 次在 `components` 内 + 0 次在 `paths` 内）。**codegen 生成出来是 `Record<string, unknown>`**。这是后端 `crud.py:544-555` 逐字交代过的取舍（挂 `response_model` 会让 `defer` 掉的大 JSON 列触发 N+1）。**处置：前端手写这 23 个 list 类型**（终审说的另一条路是给后端工厂加窄化的 `*ListRead`，**本计划不改后端**，因为那会动 Task 3 的核心工厂）。
   **⚠️⚠️ Task 1 顶回 1（Critical）：本条原来那句「list 项的键集合 = `schemas.read` 减去 `list_exclude`，且这个差集今天只有 `class-sessions` 一个非空」是说反的。** 后端 `crud.py:582-585` 逐字是 `excluded = list_exclude if list_exclude is not None else _json_text_columns(model)` —— **`list_exclude` 是「覆盖」自动探测，不是「追加」**。故**真实口径是**：
   - **list 项的键集合 = `*Read` 的字段集 减去「该资源生效的排除集」**，而**生效的排除集 = 显式 `list_exclude`（若有）否则 = 该模型的全部 `JsonText` 列**。
   - **实测相对 `*Read` 少列的是 8 个资源 / 19 列**：`interest-surveys`(2) `derived-metrics`(3) `stratification-results`(1) `exercises`(1) `prescriptions`(5) `mini-tests`(1) `alerts`(1) `weekly-class-reports`(5)。
   - ⚠️ **而 `class-sessions` 是唯一显式声明 `list_exclude=("rpe_token",)` 的资源，它恰恰是唯一差集为空的**（6 == 6，因为 `rpe_token` 早已不在 `ClassSessionRead` 上，fix 波 2 摘掉的）—— **与原句正好相反**。
   - **照原句写的后果**：8 个 list 类型会声明 API 根本不返回的字段 → 运行时 `undefined` → **管理台列表一片空白，且静默**。（Task 1 已按真口径写完并逐个核过：**23/23 对称差为空**。）
   - **⚠️ 已实测的 23 个字段数**（Task 1 报告 §6，**Task 4 的管理台照它写**）：`6/3/7/6/4/6/21/8/5/14/8/9/6/10/11/8/6/6/11/9/13/10/7`。
6. **2xx 响应 83/92 带 schema**（9 个不带的是 `204 DELETE` 与少数 `204`）。**故 codegen 对 detail 端点是可用的，只有 list 端点要手补。**
7. **23 个 detail 路径的参数名是资源单数 + `_id`**（`semester_id` / `course_section_id` / `fitness_test_result_id` / …），**不是 `pk_value`**（Task 4 专门改过，就是为了 codegen 出可读的函数签名）。
8. **错误体是统一形状**：`{"error": {"code": str, "message": str, "detail": Any | null}}`。**前端要按 `code` 分支，不要按 `message` 字符串匹配**（`message` 是给人看的中文，会变）。
   **⚠️ Task 1 已用 AST 实测出完整清单（14 个具名 + 一个通配）**，本行原来那份 11 个的清单**有 4 个不存在、漏了 8 个**：
   - **14 个具名**：`unauthenticated`(401) `forbidden`(403) `not_found`(404) `integrity_conflict`(409) `unprocessable_value`(422) `request_validation_failed`(422) `internal_error`(500) `alert_not_pending`(409) `not_recipient`(403) `no_weekly_report`(404) `rpe_not_opened`(409) `invalid_rpe_token`(403) `no_active_prescription`(404) `outside_microcycle`(404)
   - **通配**：`http_<状态码>`（今天最常见的是 **`http_405`** —— 只读资源被写时就是它）
   - ⚠️ **原清单里 4 个不存在**：`unknown_teacher` / `unknown_student`（**不在册是 403 `forbidden`**）、`rpe_already_submitted`（**重复交快评撞唯一约束 → 409 `integrity_conflict`**）、`conflict`（**逐字是 `integrity_conflict`**）。
   - ⚠️ **Task 1 顶回 3：原句给的取证方法抓不到它们** —— `Grep 'code='` 在 `backend/app` 命中 16 处**全是 `status_code=`**；15 个 `error_response(…)` 的 `code` 一律是**位置实参**。**必须用 AST。**
9. **分页是 `limit` / `offset` 查询参数，响应是 `{"items": [...], "limit": int, "offset": int, "total": int}`（⚠️ Task 1 半顶回：**是 4 个键不是 2 个**）**（`deps.Page` 是 `class Page(BaseModel)`，**不是** FastAPI 依赖函数 —— Plan 03 的控制者错误 #22 就是把它当成了依赖函数）。⚠️ **泛型 list 没有其它筛选参数**，`GET /api/alerts?rule_id=red` 这种**会被 FastAPI 静默忽略**（不报错、只返回全量）→ **前端必须客户端过滤**，或调特例端点。

### C. 语义与显示口径

10. **⚠️「不知道」不得显示成「0」。** 这是本项目最响的一条纪律，后端为此把 `completion_rate` 之类做成了 `null`。**前端遇到 `null` 必须显示「—」或「无数据」，不能显示 `0`、`0%`、`0.0`。** 已知会出现 `null` 的字段：`completion_rate`（无处方时）、`checkin_rate_by_layer[层].rate`（那一层没人时）、`mean_rpe`（那一周没有快评时）、`normalized_score`（样本不足时）。
11. **⚠️ 单人班的百分位后端给 50.0**（数学上正确：`(0 + 0.5×1)/1×100`），但**看起来像真排过名**。**前端要在 `scored_count == 1` 时显示「无排名」**（后端 `GET /api/mini-tests/normalized` 的响应里有 `scored_count`）。
12. **进步榜读 `weekly_class_report.progress_board`**（Task 9 已改成**生成周报时**算标准化得分，不再读 `mini_test.normalized_score` 列）。⚠️ **不要自己去调 `GET /api/mini-tests/normalized` 拼进步榜** —— 那会得到与周报不一致的数（两者的算式已统一到一个住址，但**窗口不同**）。
13. **减量系数**：红色预警触发 `weekly_adjustment` 的 `source='auto'`、`factor=0.8`（减 20%）。⚠️ **一处方一周至多一条 auto 调整**（fix 波 1 按用户裁定 A 落地）—— 故**同一周命中两条红色规则时，训练量仍只减 20%**，而 `alert` 表会有两行。**前端显示预警列表时会看到两条红色，但训练单上只有一个 20% 的减量**，这不是 bug，**要在 UI 上说清楚**（例如训练单上写「本周减量 20%（由 2 条红色预警触发）」）。
14. **教师端读学生训练单走 `/api/teacher/students/{student_id}/weekly-sheet`**（与学生侧 `/api/students/{student_id}/weekly-sheet` **响应体逐字相同**，因为后端把函数体抽成了 `_weekly_sheet_response` 两处共用）。⚠️ **学生侧那个端点挂的是学生头**，教师用自己的头调它会 401。
15. **⚠️ 课堂快评的口令（`rpe_token`）学生端必须做成手输。** `ClassSessionRead` **不含** `rpe_token`（fix 波 2 摘掉的），泛型 list 也 `list_exclude` 了它；教师端要显示口令只能调 **`GET /api/class-sessions/{id}/rpe-token`**（教师头）。**故学生端的流程是：教师投屏 → 学生手输口令 → 提交 RPE**，不是「学生端自动拿到口令」。
16. **`rpe_opened` 为假时读口令是 409 `rpe_not_opened`**（不是 404、不是 `null`）。学生提交快评撞上同一档也是这个 code。
17. **三个动作值**：`POST /api/alerts/{alert_id}/handle` 的 `action` ∈ `ACTION_REDUCE` / `ACTION_IGNORE` / `ACTION_NOTE`（常量住在 `app/api/routers/alerts.py`）。
   **⚠️ Task 1 顶回 4：原句「前端要从 `/openapi.json` 读枚举」做不到** —— `AlertHandleCreate.action` 在 schema 里逐字是 `{"type":"string","title":"Action"}`，**闸门是 `field_validator`，而 validator 不进 JSON Schema**；**全库唯一的 enum schema 是 `OverrideKind`**。
   **处置（Task 1 已落地）**：三档**字面写出**，并在 **Task 5 的联调脚本里加一条对拍守卫**（逐个 `POST` 一个非法 `action` 断言 422；再断言三档合法值都被接受）—— **这是「枚举不在契约里」时唯一能做的机器守卫**。
18. **`level` ∈ `red` / `yellow` / `green`**（`AlertLevel` 是所有者，`Alert.LEVELS` 是 DB 镜像）；**`status` ∈ `pending` / `handled` / `ignored`**。**预警去重靠 DB**：同一 `(rule_id, subject_key, semester_id, window_key)` 只有一行，故**前端不需要自己去重**。
19. **`weekly_class_report` 是每周日生成的**（`is_report_day` 判据）。⚠️ **非周日没有当周的周报** → 前端要处理「本周周报尚未生成」这一档（不要显示成一堆 0）。
20. **23 个资源里 14 个是只读的**（`writable=False`），其中 **`exercises` 与 `prescription-templates` 是刻意只读**（spec §4.4 逐字：「这是体育专家维护的知识资产……改阈值应走版本控制与评审，不应在运行时改数据库」）。**前端的管理台必须把只读资源的「新建/编辑/删除」按钮做成不出现（不是禁用）**，并说明理由。

## 2. 美学方向（`frontend-design` 技能的要求：选一个极端、执行到底）

**方向：《田径场年鉴》（Athletics Almanac）—— 计时牌 × 编辑部排印。**

不是「又一个后台管理模板」。这个系统的两个真实场景是**操场边**与**教室大屏**，故视觉语言取自**田径场的分道线与电子计时牌**：

- **主色**：`--ink: #14110F`（暖近黑，不是纯黑）与 `--paper: #F4F0E6`（米白纸张，不是纯白）。**大面积是纸与墨，红色只作锐利点缀**（技能的「dominant colors with sharp accents」）。
- **锐利点缀**：`--track: #BE3F2B`（跑道砖红 / terracotta）—— 用在**分道线、当前项的高亮、红色预警**。
- **语义三色**（预警必须能一眼分辨，且要与 `--track` 区分开）：`--red: #B3352B`、`--amber: #C98A22`、`--moss: #4C7A57`。⚠️ **三色都要在 `--paper` 与 `--ink` 两种底上通过对比度检查**（大屏是投影，对比度不够就全糊了）。
- **字体**（⚠️ 技能明令禁止 Inter / Roboto / Arial / system-ui，也点名不要收敛到 Space Grotesk）：
  - **数字与拉丁标题 = `"Barlow Condensed"` 600/700/800** —— 窄体无衬线，读起来就是**计时牌/成绩单**，且它不像 Bebas Neue 那样被用滥。
  - **中文标题 = `"Noto Serif SC"` 700/900** —— 宋体的笔画粗细对比给「年鉴/编辑部」的分量。
  - **正文 = `"Noto Sans SC"` 400/500**。
  - **数据表格与代码 = `"JetBrains Mono"` 400/600**（`font-variant-numeric: tabular-nums` 必开，否则数字列对不齐）。
  - ⚠️ **全部走 Google Fonts 的 CDN**，并在 `index.html` 里 `preconnect`；⚠️ **必须给出 `font-family` 的中文回退栈**（`"PingFang SC", "Microsoft YaHei", sans-serif`），否则离线时中文会掉到宋体默认。
- **母题（让它「过目不忘」的那一件事）**：**分道线**。所有区块的分隔不用普通 `border`，而用**「一条粗线 + 一条细线 + 左端的道次编号」**（`01` `02` `03`…，Barlow Condensed 800、极小字号、`--track` 色）。**大屏的每个卡片左上角都有一个道次编号**，学生端的每个步骤也是。
- **纹理**：`--paper` 上叠一层极淡的 SVG 颗粒（`feTurbulence`，opacity 0.035），模拟**纸张/跑道颗粒**；大屏的底色叠一层极淡的**跑道弧**（一个大半径的 `radial-gradient` 偏在一角）。
- **动效**：**克制、只用在高价值时刻** —— ① 页面载入时**分道线从左到右划出**（`transform: scaleX(0→1)`，`transform-origin: left`，各区块 `animation-delay` 递增 60ms，形成 staggered reveal）；② **数字滚动到位**（计时牌的感觉，只用于大屏的关键指标与学生的本周训练量）；③ 打卡/RPE 提交成功时**一个「盖章」动效**（`scale(1.4→1)` + 一次轻微旋转 + 印泥色扩散）。**不做**无意义的 hover 浮动、不做视差滚动。
- **布局**：**不对称、允许重叠**。学生端是单列但**卡片故意出血到屏幕边缘**（`margin-inline: -16px` 配 `padding-inline: 16px`）；教师大屏是 **12 列网格但故意让「预警队列」跨 5 列、「分层分布」跨 4 列、「本周概览」跨 3 列**（不是均分三列）。

## 3. 技术选型

| | 选择 | 理由 |
|---|---|---|
| 构建 | **Vite 8** | spec 逐字指定 |
| 框架 | **Vue 3.5 + `<script setup lang="ts">`** | spec 逐字指定 |
| 路由 | **Vue Router 4** | spec 逐字指定 |
| 状态 | **Pinia 3** | spec 逐字指定；只存三样：当前身份、当前学期/`as_of`、服务端缓存 |
| 样式 | **纯 CSS + 自定义属性 + `scoped`** | ⚠️ **不用 Tailwind / UnoCSS**。理由：本计划的美学方向要靠**分道线母题、纸张纹理、计时牌数字**这些 bespoke 的东西撑起来，原子化 CSS 会把它们打散成一堆 utility，**而技能明令禁止「cookie-cutter design」**。设计令牌集中在一个 `tokens.css` 里，这已经是原子化想要的好处 |
| 图表 | **手写 SVG**（不引 ECharts） | 需要的图只有 4 种（分层分布、RPE 趋势、三层完成率、进步榜），**手写才能做出「年鉴」的味道**（ECharts 的默认皮肤一眼就是后台模板），且数据形状都很简单 |
| HTTP | **`fetch` + 一层薄封装**（不引 axios） | 需要的只有：注入身份头、统一错误体解析、`as_of` 查询参数。axios 换来的是一层抽象而不是能力 |
| 类型 | **`openapi-typescript` **7.13.0** 生成 + 23 个手写 list 类型** | 见 Global Constraints 第 5 条。**⚠️ Task 1 顶回 2（Critical）：v7 的取值路径与本计划原先设想的不同** —— v7 的 `paths` 里每个 method **只有一行** `get: operations["list_rows_api_students_get"]`，**响应体内联在 `operations` 侧**。故 Task 2–4 一律照这四条取值：模型 `components['schemas']['StudentRead']`；响应体 `operations['<operationId>']['responses'][200]['content']['application/json']`；参数 `operations[op]['parameters']['query' \| 'header']`；**`operationId` 是 FastAPI 自动生成的**（`list_rows_api_x_get` / `read_one_api_x__pk__get` / `create_row_api_x_post`）。⚠️ **`endpoints.ts` 刻意只走 `components['schemas']` + 手写 list 类型、不依赖 `paths` 的形状**，故 v7→v8 的升级代价被隔离在 0。产物 **338 756 B / 7 971 行**，重跑 SHA256 逐字不变 |
| 测试 | **不做单测；只做 Task 5 的真实联调脚本** | 见「非目标」 |

⚠️ **`frontend/` 目录今天在 `.gitignore` 里被忽略了**（Plan 01 时占位的，`.gitignore:29-31` 的 node_modules 段之外还有一行 `frontend/`）→ **Task 1 必须先把它从 `.gitignore` 里去掉**，否则前端代码全部不入库。

### Task 4：管理台（一个通用组件 + 一份资源目录，不是 23 套页面）

**Files**：`src/views/admin/*`、`src/catalog/resources.ts`

⚠️ **这是本计划里最容易做过头的一节。** 后端用**一个泛型工厂**生成了 23 个资源的路由，故前端也用**一个通用组件** + **一份 23 行的资源目录**。**不要手写 23 套页面** —— 那会产生 23 份互相不一致的分页/错误/空态行为。

**`catalog/resources.ts` 的 23 行，每行要给**：`resource`（后端的路径段）/ `titleZh`（中文标题）/ `writable`（**必须与后端 `RESOURCES` 的 `writable` 逐字一致**）/ `onDelete`（`restrict` / `forbid` / `cascade`）/ `pkField`（`semester_id` 之类）/ `displayFields`（列表页显示哪几列，**从 `*Read` 的字段里挑 4–6 个**）/ `listExclude`（今天只有 `class-sessions` 是 `["rpe_token"]`）。

**三个页面**：`ResourceIndex`（23 个资源的目录，**只读的 14 个要标出来并说明理由**，第 20 条）/ `ResourceList`（分页 + 新建 + 行内删除）/ `ResourceDetail`（读单条 + 编辑）。

**⚠️ 只读资源的「新建/编辑/删除」按钮要「不出现」而不是「禁用」**（第 20 条），并在页面上写一句 spec §4.4 的理由。
**⚠️ `on_delete='restrict'` 的资源删除失败会返回 409**（有子表指着它）→ 错误横幅要说清「这个 X 还被 N 个 Y 引用」，**不要只显示 `conflict`**。
**⚠️ `on_delete='forbid'` 的 10 个资源是批处理产物**（`fitness-test-batches` / `prescriptions` / `alerts` / `notifications` / `weekly-class-reports` / …）→ **DELETE 端点根本不存在**（后端返回 405），故**按钮不出现**，并写明「这是管道产物，要改请重跑批处理」。

**验收**：23 个资源全部能在管理台里读到列表与详情；**9 个可写资源能新建/编辑/删除**；**14 个只读资源看不到任何写按钮**；删除一个被引用的资源能看到人话错误。
