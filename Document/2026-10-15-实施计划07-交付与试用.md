## 0. 本计划要解决的四件事

1. **今天没有一条能让甲方点开的链接**：`scripts/serve.ps1` 只听 `127.0.0.1`，而甲方不在这台机器上。本机的局域网地址是 `192.168.31.11`（WLAN），机器上没有任何隧道工具（`cloudflared` / `ngrok` / `frpc` 都 MISSING），但有 `winget` 与 OpenSSH，出网 443 通。
2. **没有「试用档」这个概念**：`backend/pe_demo.db` 既是开发靶子又是演示数据，`smoke.mjs` 一跑就脏（它自己印一段「已经写脏了演示库」）；而页面上**没有任何一处**告诉访问者「这是试用环境、数据是高保真仿真、请勿录入真实学生信息」——甲方完全可能把真学生的体测数据敲进去。
3. **没有可分发产物**：Plan 06 Task 7 自己登记过「`serve.ps1` 是『在这台机器上起服务』，不是『产出可分发 zip』」。甲方 IT 想在自己机器上起一份，今天要 clone 仓库 + 装 Python + 装 Node + `npm install` + `npm run build`。
4. **甲方试用说明书不存在**：唯一的 run book 是 spec §13，**4601 行**，那是给开发者与对接工程师读的，不是给试用者读的。仓库根的 `README.md` 是 60 行的开发者入口。

## 1. Task 1 —— 试用档基座：专用库 + 一键重置 + 页面告示

- **试用库与演示库分开**：`backend/pe_trial.db`（⚠️ 进 `.gitignore`；⚠️ 禁区 `backend/pe.db` 仍然不许存在；⚠️ `backend/data/**` 一字节不许动）。
- `scripts/trial.ps1`：**一条命令** = 灌一份全新试用库（走 `demo.ps1` 的**同一套**生成器，⚠️ 不写第二个数据生成器）→ 起产品档 → 打印试用链接与账号。
- `-Reset`：删掉旧试用库重灌（甲方试用一定会写脏：绑定、打卡、快评、预警处置）。
- **页面上挂一条试用告示**，一处住址（根组件），**16 条路由都看得见**：「试用环境 · 数据为高保真仿真 · 请勿录入真实学生信息」。
  - ⚠️ **档位不能写死在构建产物里**（否则同一份 `dist` 在开发档也挂告示）→ 由**后端**告诉前端「这是什么档」（⚠️ 挂在 `/api/health` 上还是新开一个端点，实现者定并说明；⚠️ 新端点会让 openapi 五格变，要同步全部钉这些数的断言）。
  - ⚠️ 用既有 token，**不新增裸值**，`check:tokens` 不许退；⚠️ 不许破 DOM 守卫（重叠 / 横向溢出 / 按档取的字节地板）。
- 守卫：告示在**试用档 16 条路由都在**、在**开发档不在**；一键重置之后端到端仍可登录；定点变异（把档位判定反过来）要红。

## 2. Task 2 —— 局域网档：`serve.ps1` 的 `-Lan`

- `-Lan` → bind `0.0.0.0`（**缺省仍 `127.0.0.1`**，一格都不许变），并打印本机**全部** LAN IPv4 的 URL。
- **防火墙**：打印一条 `netsh advfirewall` 命令 + 一句为什么。⚠️ **不自动改防火墙**（那要管理员权限，而静默提权不是交付物该有的形状）。
- ⚠️ **档位裁定**：局域网是**明文 http** → 必须留在 `dev` 档（`prod` 会开 cookie 的 `Secure`，明文 http 上浏览器拒收 → 症状是「登录 200、下一个请求 401」）。⚠️ 这一格 Plan 06 Task 7 已经论证过并写进 spec §13.11.3，**本计划不推翻它**。
- ⚠️ 打印一段**响亮**的告示：这是明文局域网试用、不要传真实数据、口令是公开的。
- 守卫：`-Lan` 与缺省两档的**绑定地址实测**（`Get-NetTCPConnection` 的 `LocalAddress`）；dev 档 cookie 无 `Secure`、prod 档有（两档逐字对比）。

## 3. Task 3 —— 公网隧道：`cloudflared` + `scripts/tunnel.ps1`

- 用 `winget` 装 `cloudflared`。⚠️ **先实测能不能装上**；装不上就**顶回来**并给替代方案（本机有 OpenSSH，`ssh -R 80:localhost:<port> nokey@localhost.run` 是一档零安装的公网隧道）。
- `scripts/tunnel.ps1`：起 `cloudflared tunnel --url http://127.0.0.1:<port>` → 从它的输出里抓出 `https://<rand>.trycloudflare.com` → 打印 + **写进一个 gitignore 的文件**（链接要能被别人读到，而不只闪在终端上）。
- ⚠️ **档位裁定**：隧道**边缘是 HTTPS**，故这一档可以（也应当）跑 `prod`：`Secure` cookie 在浏览器侧成立、同源故不需要 CORS、请求头身份通道强制关、启动自检会跑。⚠️ **必须端到端实测**「登录 → 下一个请求 200（不是 401）」；**若实测 prod 在隧道下不通，退回 dev 并如实记**（不要为了好看硬撑一档登不进去的配置）。
- ⚠️ **链接生命周期**：quick tunnel 的 URL **每次重开都变**、进程死了就失效 → 脚本必须把这一句印出来，不许让人以为链接是永久的。
- ⚠️ **公网暴露的风险告示**（打印 + 写进说明书）：演示口令是公开的、未绑定账号可被抢绑（spec §1.2 第 4 条）、GET 读操作今天不留审计（spec §1.2 第 14 条 / §13.9）。
- 守卫：URL 形状可取；prod 档在隧道下的 cookie 属性实测；隧道进程死后端口归零。

## 4. Task 4 —— 可分发 zip：`scripts/package.ps1`

- 产出 `dist-pack/pe-ims-trial-<ts>.zip`（⚠️ 进 `.gitignore`）。
- **内容**：`backend/`（含 `data/` 那 24 个指纹文件）+ `frontend/dist`（**预构建**）+ `Document/`（spec 与计划文档 = **技术对接依据**，spec §1.2 明写这是本原型的三个目的之一）+ `README.md` + `scripts/` + 一个一条命令起试用的入口脚本。
- **排除**：`.git`、`node_modules`、`__pycache__`、`*.db`、`backups/`、`.superpowers/`（内部账本，不是给甲方的）。
  - ⚠️ **`frontend/src` 带不带**：控制者裁定**带**（甲方 IT 可能要读，而 spec 是对接依据）；⚠️ **若实现者实测认为「带 src 但不带构建链」会造成困惑**（例如包里 `npm run build` 跑不起来又摆着 `package.json`），**顶回来**。
- ⚠️ **只依赖 Python 3.11+**（不需要 Node —— `dist` 是预构建的）→ 包里必须有**前置检查**与一句人话的报错（照 `serve.ps1` ① 那一步的姿势）。
- ⚠️ **包里不放 `.db`**：首次启动自己灌（走 Task 1 的同一条路径，⚠️ 不写第二个灌库器）。
- 守卫（**本 Task 的核心可执行判据**）：**解包到一个临时目录** → 在**只有 Python**的前提下 → **一条命令**起服务 → `/api/health` 200 且 16 条路由各 200 → 停干净。⚠️ 这一条不许用「读代码觉得应该行」代替。
