## 0. 本计划要解决的四件事（**每一件都已经在交付须知里向甲方念过**）

1. **读操作一行都不留痕**。今天 `audit_log` 只记**写**与登录/绑定（Plan 07 Task 9 实测：几百个 GET **一行都没记**，`group by method` = `[('POST', 47)]`）。甲方是体育**健康**数据（出生日期、体成分、体测、处方、预警），而「**谁翻过谁的档案**」库里查不到 —— 这一格写在 **spec §1.2 第 14 条**与 **§13.15 交付须知第 3 条**，也写在甲方试用说明书 §6 的须知里（排最前四条之一）。
2. **三张表无限增长、备份永不删**。`login_attempt` / `user_session` / `audit_log` **没有任何清理任务**（spec §13.15 第 5 条：「三张表无清理任务」）；`backend/scripts/backup.ps1` 每跑一次产一份全量库副本 + 一个 `.sha256` 侧车，**从不删旧的**（Plan 07 Task 4 登记过同族的 `dist-pack\` 累积）。长跑必然膨胀，而膨胀的是**含个人健康数据**的副本。
3. **备份是明文的**。`backup.ps1` 的产物就是原库文件的逐字节副本，Plan 07 Task 9 **实测**：「文件头 `SQLite format 3\0`、**不用任何密钥**就读出 60 人姓名与出生日期、240 行体成分、47 行审计」。⚠️ 备份文件往往被拷到 U 盘 / 网盘 / 邮件附件，**这一格比在线库更危险**（在线库至少有权限与防火墙，一个 U 盘没有）。
4. **未绑定账号可被抢绑**。spec §1.2 第 4 条与交付须知第 4 条：任何教职账号都能读全校 **60** 人名册（**含 `birth`**），并据此替**未绑定**的账号设口令。⚠️ 今天自助绑定的验身材料只有「**学号 + 出生日期**」，而这两格**对教职都是已知的** ⇒ 验身材料等于零。

## 1. Task 1 · 读审计：**敏感读**留痕（⚠️ 不是「所有 GET 都记」）

- ⚠️ **控制者裁定的判据**：**只记敏感读**，不记全部 GET。理由：全部 GET 会把 `health`/`docs`/静态资源/前端轮询都记进去，**量级会淹掉真正要看的那几行**，而甲方要的是「谁翻过谁的档案」。
- **敏感读的清单**（⚠️ 实现者要**自己从 openapi 的 63 个 GET 里挑并逐个说明理由**，控制者给的候选：学生详情 / 名册（含 `birth`）/ 周训练单 / 处方 / 体成分 / 体测结果 / 小测成绩 / 预警队列 / 班级周报 / 审计页本身）—— ⚠️ **判据要写在代码里且单一所有者**（一个「这一路径算不算敏感读」的函数，⚠️ 不许每个 router 各自判）。
- **存哪儿**：⚠️ **裁定新开一张表**（例如 `read_audit_log`），**不复用 `audit_log`**。理由：① 量级差一个数量级，混在一张表里管理台那页会被淹；② `audit_log` 的九列形状已被守卫与管理台页钉住，塞进去要动那两处；③ 留存策略不同（读审计应当比写审计**更早**清）。⚠️ **若实现者认为复用更对，顶回来给成本对比。**
- ⚠️ **迁移链 4 → 5**（新表），⚠️ **`downgrade` 必须真能跑**（Plan 06 Task 4 在迁移 4 上留过一个跑不通的 `downgrade`，已登记 §15 C3 —— **本波不许再犯**）。
- ⚠️ **永不落请求体**这条**结构性保证**（Plan 06 Task 9 做的）在读审计上**同样成立**，要有守卫钉住。
- **管理台**：⚠️ **裁定不新开一个页面**，而是在既有 `/admin/audit-logs` 上加一个「写 / 读」的切换（⚠️ 新开页面会让路由数 16 → 17，而 smoke 第 14 步、说明书 §5、README 三处都钉着 16；⚠️ **若实现者认为该新开一页，顶回来并说明这三处怎么改**）。
- 守卫：敏感读**逐条**留痕、非敏感读**逐条不留痕**（⚠️ 反空转，两侧不同源）、学生读自己的档案**记不记**要有一个明确裁定并被钉住、`read_audit_log` 的行数上界、⚠️ **定点变异**（把敏感清单去掉一条 → 拍红）。

## 2. Task 2 · 留存清理：四张表的过期行

- **一个 CLI**（⚠️ 照 `app.seed`/`backup.ps1` 的既有姿势，⚠️ **不写第二个清理器**）：按**天数**或**行数**清 `login_attempt` / `user_session`（已过期的）/ `audit_log` / `read_audit_log`。
- ⚠️ **保留窗口的缺省值要有理由**（控制者建议：会话 7 天、登录尝试 90 天、写审计 **不少于 1 年**、读审计 90 天 —— ⚠️ **实现者要核 spec §13.4.6 与 §13.9 有没有已经写下的口径**，有就照它，没有就提议并说明）。
- ⚠️ **失效方向**：清理是**破坏性**操作 ⇒ 必须**先打印将删多少行、再删、删完复核**，⚠️ **且要有 `--dry-run`**；⚠️ **不许静默删**。
- ⚠️ **怎么被周期性地跑**：Windows 上没有 cron ⇒ **裁定给一个注册计划任务的脚本 + 一段文档**（⚠️ **不自动注册**，与 `serve.ps1` 不自动改防火墙同一条口径：静默改甲方的机器不是交付物该有的形状）。
- 守卫：四张表各自的清理判据、`--dry-run` **一行都不删**（⚠️ 这一拍是核心）、删完的行数与预告逐字相符、⚠️ **定点变异**（把 `--dry-run` 的短路去掉 → 拍红）。

## 3. Task 3 · 备份加固：保留策略 + 可选加密

- **保留策略**：`backup.ps1` 加一个 `-Keep <N>`（⚠️ **缺省不删**，保持今天的行为一格不变；⚠️ 删之前**逐个打印**要删哪几份与它们的字节数/sha）。
- **加密**：⚠️ **裁定用 .NET 的 `System.Security.Cryptography`（AES-256-GCM 或 CBC+HMAC）在 PowerShell 侧做，密钥从环境变量 `PE_BACKUP_KEY` 读** —— 理由：**新增依赖必须仍是 0**（`pyproject.toml`/`package.json` 一个字不许改，依赖清单守卫钉着），而 BCL 不算依赖。⚠️ **若实现者认为 .NET 那一套在 PS 5.1 下不可靠**（例如 AES-GCM 在 .NET Framework 4.x 上没有），**顶回来**并给替代（例如 AES-CBC + 独立的 HMAC 侧车）。
- ⚠️ **密钥怎么管**：**不许写死、不许入库、不许打印**；⚠️ **缺 `PE_BACKUP_KEY` 时的行为要明确**（裁定：**不加密**并打印一段响亮的 ⚠️ 说明「这一份是明文的」，⚠️ 而不是 raise —— 因为今天的缺省行为就是不加密，raise 会把既有用户打死）。
- ⚠️ **`restore.ps1` 必须能吃加密备份**（⚠️ 且**吃错了要响亮**：密钥不对时不许静默产出一个坏库）。
- ⚠️ **加密后 Plan 06 Task 10 那三档取证（篡改 / 写锁 / 跨链版本）必须仍然成立**，⚠️ 加密那一层要**新增**一档：**密钥不对**。
- 守卫：明文档与加密档的产物形状、`-Keep` 的删除清单、缺密钥时那段 ⚠️ 在、⚠️ **定点变异**（把「缺密钥就打印 ⚠️」去掉 → 拍红；把 `-Keep` 的打印去掉 → 拍红）。
