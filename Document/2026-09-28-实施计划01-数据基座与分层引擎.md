# 计划 01：数据基座与分层引擎 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立后端骨架、数据模型、高保真仿真数据与每日批处理管道，跑通「原始体测数据 → 国标得分 → 校内百分位 → 短板/体成分/趋势 → 红黄绿分层」全链路，500 人逐人可追溯。

**Architecture:** 模块化单体 FastAPI。`domain/` 为无 I/O 纯函数层，承载全部研究结论（评分表、短板判定、分层规则）；`pipeline/` 按业务日期幂等编排；`adapters/` 通过 `DataSourceAdapter` 接口隔离乐跑数据源，使未来接真实只读接口的改动限于单个实现文件。SQLite + SQLAlchemy，Repository 模式封装持久化。

**Tech Stack:** Python 3.11+、FastAPI、SQLAlchemy 2.x、pandas/numpy、pytest、SQLite

**Spec:** `Document/2026-09-28-体育闭环原型-设计spec.md`

## Global Constraints

- Python **3.11+**；数据库为 SQLite 单文件 `backend/pe.db`；ORM 为 **SQLAlchemy 2.x**
- `app/domain/` 层**禁止任何 I/O**：不得 import `sqlalchemy`、`fastapi`、`requests`，不得调用 `open()`、`datetime.now()`、`random` 无种子接口；时间与随机数一律由调用方注入
- **参考表（国标评分表、国标常模）由 `app/refdata.py` 加载，它是全仓唯一被允许读 `backend/data/*.csv` 的模块**；domain 函数一律**显式接收表对象**作为首参，不得在 domain 内做任何默认加载。依赖方向为 `refdata → domain`，domain 保持叶子。此条由架构测试的文件访问模式检查强制（Ruling 15）
- 指标口径（spec §4.2，**决定 `W` 的分母**）：**8 项原始测量 → 7 个国标计分项（身高体重合成 BMI）→ 6 个短板判定项（排除 BMI）**。BMI 不计入短板，避免与体成分维度 `C` 重复计数
- 国标评分依据《国家学生体质健康标准（2014 年修订）》
- 百分位分组维度：**同校区 × 同性别 × 同龄组**；必须物化为 `percentile_snapshot`，**禁止实时计算**
- 幂等键：`(semester_id, business_date)`，在 `daily_sync_run` 上为唯一约束
- `valid_count < 4`（共 6 个短板判定项）→ 本日不分层，标签置 `insufficient_data`
- 分层规则共 **7 条**：`R1 R2 Y1 Y2 Y3 Y4 G1`，按优先级**命中即停**，全部命中规则 ID 落库
- 仿真数据由单一 `--seed` 驱动，默认 **`20250828`**；同 seed 输出**字节级一致**
- 目标分层分布默认 **红 20% / 黄 45% / 绿 35%**，容差 **±5%**
- 体成分异常 `C` 阈值：体脂率 **男 > 20%、女 > 28%**，或肌肉量 **< 同龄同性别 P20**
- 骨骼肌指数**第一批不参与** `C` 判定（入库但不判定）
- 趋势标签仅作**升级项，永不降级**（规则 Y4）
- 500 人批量管道回放 **< 60 秒**
- 代码注释、commit message、用户可见文案一律**中文**
- 本仓库在 **Windows / PowerShell** 下开发：所有 `Run:` 命令中出现的 `&&` 一律按 `;` 执行（PowerShell 不支持 `&&` 作语句分隔符）。PowerShell 亦不支持 heredoc，提交中文信息须写入无 BOM 的 UTF-8 临时文件后用 `git commit -F`，提交后删除临时文件
- 每个 Task 结束必须 commit；禁止跨 Task 累积未提交改动

## Review Focus

spec 隐含但任务测试容易漏掉的五类输入与失效模式，按最可能伤到使用者的顺序排列。每条已在所属 Task 中落地为具体测试。

1. **国标评分表分段边界值** — 如 1000 米跑恰好等于某档阈值秒数时，应取该档得分，不得因浮点误差掉档 → Task 2 `test_score_at_segment_boundary`
2. **单项缺失导致 `valid_count` 变化** — `W` 必须按有效项计，缺失项**绝不当 0 分**；`valid_count < 4` 时不分层 → Task 8 `test_missing_item_not_counted_as_zero`、Task 9 `test_insufficient_data_when_valid_count_below_4`
3. **量纲错误**（身高录成 `1.75` 米而非 `175` 厘米）— 应启发式识别、×100 修正并写 `cleaning_log` → Task 5 `test_unit_error_height_in_meters_normalized`
4. **某性别龄组样本 < 30 人** — 百分位不可靠，应降级到国标常模并标记 `percentile_source = national` → Task 7 `test_snapshot_falls_back_to_national_when_sample_below_30`
5. **同业务日期重跑** — 派生数据必须完全一致且无重复行 → Task 10 `test_rerun_same_business_date_is_idempotent`

```python
# backend/tests/architecture/test_domain_purity.py
import ast
import pathlib
import re

DOMAIN = pathlib.Path(__file__).parents[2] / "app" / "domain"
# 与 spec Global Constraints 逐条对应：禁 I/O 库、禁无种子随机数
FORBIDDEN = {"sqlalchemy", "fastapi", "requests", "httpx", "pydantic_settings", "random"}
# 时间必须由调用方注入；子串检查足以覆盖这五种写法
FORBIDDEN_CALLS = {"datetime.now", "datetime.today", "datetime.utcnow", "date.today", "time.time"}
# open 用词边界正则而非裸子串，避免 open_ended / reopen / 注释里的 "open" 误报
FORBIDDEN_PATTERNS = (re.compile(r"\bopen\s*\("),)

def test_domain_has_no_forbidden_imports():
    # 守卫：Path.rglob() 对不存在的目录静默返回空，缺了这行测试会空转全绿
    assert DOMAIN.is_dir(), f"领域层目录缺失，架构测试将空转: {DOMAIN}"
    offenders = []
    for py in DOMAIN.rglob("*.py"):
        tree = ast.parse(py.read_text(encoding="utf-8"))
        for node in ast.walk(tree):
            mods = []
            if isinstance(node, ast.Import):
                mods = [a.name.split(".")[0] for a in node.names]
            elif isinstance(node, ast.ImportFrom) and node.module:
                mods = [node.module.split(".")[0]]
            offenders += [f"{py.name}:{m}" for m in mods if m in FORBIDDEN]
    assert offenders == []

def test_domain_has_no_clock_or_file_access():
    assert DOMAIN.is_dir(), f"领域层目录缺失，架构测试将空转: {DOMAIN}"
    offenders = []
    for py in DOMAIN.rglob("*.py"):
        src = py.read_text(encoding="utf-8")
        offenders += [f"{py.name}:{c}" for c in FORBIDDEN_CALLS if c in src]
        offenders += [f"{py.name}:{p.pattern}" for p in FORBIDDEN_PATTERNS if p.search(src)]
    assert offenders == []
```

`FORBIDDEN` 含 `random` 是导入级全禁而非只禁调用：spec 要求「随机数一律由调用方注入」，调用方传入已播种的 `random.Random(seed)` 或 `np.random.Generator` 实例即可，domain 模块自身无需 `import random`。numpy 不在禁列（Task 7 的 `np.percentile` 是合法纯计算）。

**Interfaces:**
- Consumes: Task 1 的架构测试与包结构
- Produces:
  - `class Sex(str, Enum)`: `MALE = "male"`, `FEMALE = "female"`
  - `class ScoredItem(str, Enum)`: `BMI`, `VITAL_CAPACITY`, `SPRINT_50M`, `SIT_AND_REACH`, `STANDING_JUMP`, `PULL_UP_OR_SIT_UP`, `DISTANCE_RUN`（**7 项**）
  - `WEAKNESS_ITEMS: tuple[ScoredItem, ...]` — **6 项，不含 `BMI`**
  - `ITEM_BUCKET: dict[ScoredItem, str | None]` — `DISTANCE_RUN`/`VITAL_CAPACITY` → `"endurance"`；`PULL_UP_OR_SIT_UP`/`STANDING_JUMP` → `"strength"`；`SPRINT_50M`/`SIT_AND_REACH` → `"speed_flexibility"`；`BMI` → `None`
  - `AGE_GROUPS: tuple[str, ...]` — 按国标 2014 分组
  - `age_group_of(age: int) -> str`
  - `@dataclass(frozen=True) StandardTable`（在 `app/domain/tables.py`），结构固定为：
    ```python
    segments: dict[tuple[str, str, str], tuple[tuple[float, int], ...]]
    # 键 = (item.value, sex.value, age_group)
    # 值 = 按原始值升序排列的 (raw_value, score) 档位序列
    ```
  - `score_item(table: StandardTable, item: ScoredItem, value: float | None, sex: Sex, age_group: str) -> int | None` — 正查，**就低取档阶梯查表，不做插值**（Ruling 18）。越界**夹到对应端点档位分**（Ruling 17）。`None` 只在两种情况返回：`value is None`、或 `(item, sex, age_group)` 键不存在
  - `raw_from_score(table: StandardTable, item: ScoredItem, score: int | float, sex: Sex, age_group: str) -> float` — 反查，供仿真数据生成。**不做插值**（Ruling 18/22）：请求分先就低映射到「不超过它的最大官方档」，再返回**方向感知的档位端点**——越大越好取该档 raw 区间下端点，越小越好取上端点，即「仍能取得该分的最差成绩」。因此 `score_item(table, item, raw_from_score(table, item, s, ...), ...) == s` 对每个官方档 `s` **精确成立**，且次数项（引体向上/仰卧起坐）返回值天然是整数，**Task 6 无需任何取整**。非单调序列（即 BMI）抛 `ValueError`，键不存在抛 `KeyError`。`score` 标注为 `int | float` 因为 Task 6 传入的是 `clip(70+15·latent+N(0,5),0,100)` 的连续目标分
  - `segment_thresholds(table: StandardTable, item: ScoredItem, sex: Sex, age_group: str) -> list[float]` — 该组全部档位原始值阈值，升序；**键不存在抛 `KeyError`**（与 `raw_from_score` 对齐）
  - `app/refdata.py`：`DATA_DIR: pathlib.Path`、`load_standard(path: pathlib.Path | None = None) -> StandardTable`（`path` 缺省为 `DATA_DIR / "national_standard_2014.csv"`；文件不存在抛 `FileNotFoundError`；**逐行校验 `item`/`sex`/`age_group` 是否属于对应枚举，失败抛带 CSV 行号的错**）、`standard() -> StandardTable`（进程内单例缓存，**缓存放在 refdata 而非 domain**）
  - `StandardTable.segments` 以 `types.MappingProxyType` 包装，`tables.py` 中字段类型标注为 `collections.abc.Mapping`（Minor 9：`frozen=True` 只是浅不可变，而 `standard()` 是全进程共享单例）。**已知代价**：表对象因此不可 pickle / deepcopy / `dataclasses.asdict`；Task 11 若为性能引入多进程，须让各 worker 自行调 `refdata.standard()` 而非跨进程传表
  - ~~`segment_count(...)`~~ — **已移除**：它委托给 `segment_thresholds`，后者改抛 `KeyError` 后它再也不可能对缺失组合返回 0，与其「完整性校验」用途不相容，且覆盖测试改用键集合相等断言后已无调用方。代码中的残留函数为死代码，待终审删除；**后续任务不得使用**

> **Ruling 15 要点**：`score_item` / `raw_from_score` / `segment_thresholds` 的**首参一律是表对象**。domain 内不得出现任何默认加载、模块级缓存或文件读取——否则 domain 会隐式依赖磁盘上某个 CSV 是否存在，spec §1.3「逐人可追溯」与 §12「黄金用例」就都站不住。加载与缓存全部由 `app/refdata.py` 承担，依赖方向 `refdata → domain`，domain 仍是叶子。

```python
# backend/tests/domain/test_indicators.py
from app.domain.indicators import (
    Sex, ScoredItem, WEAKNESS_ITEMS, ITEM_BUCKET,
    age_group_of, score_item, raw_from_score, segment_thresholds,
)
from app.refdata import standard

T = standard()          # 表由 refdata 加载后注入，domain 自身不读盘（Ruling 15）
G = age_group_of(19)

def test_weakness_items_exclude_bmi():
    assert len(WEAKNESS_ITEMS) == 6
    assert ScoredItem.BMI not in WEAKNESS_ITEMS

def test_scored_items_count_is_seven():
    assert len(list(ScoredItem)) == 7

def test_buckets_cover_all_weakness_items():
    assert {ITEM_BUCKET[i] for i in WEAKNESS_ITEMS} == {
        "endurance", "strength", "speed_flexibility"}
    assert ITEM_BUCKET[ScoredItem.BMI] is None

def test_direction_is_normalized_to_higher_is_better():
    # 50 米跑越快得分越高
    assert score_item(T, ScoredItem.SPRINT_50M, 6.5, Sex.MALE, G) > \
           score_item(T, ScoredItem.SPRINT_50M, 9.0, Sex.MALE, G)

def test_score_at_segment_boundary():
    # Review Focus #1：恰好等于档位阈值时不得因浮点误差掉档。
    # 阈值从评分表本身取，避免硬编码魔数与 CSV 内容脱钩。
    thr = segment_thresholds(T, ScoredItem.SPRINT_50M, Sex.MALE, G)[3]
    at_thr     = score_item(T, ScoredItem.SPRINT_50M, thr, Sex.MALE, G)
    just_worse = score_item(T, ScoredItem.SPRINT_50M, thr + 1e-9, Sex.MALE, G)
    assert at_thr == just_worse
    assert at_thr is not None

def test_sex_specific_items_differ():
    m = score_item(T, ScoredItem.PULL_UP_OR_SIT_UP, 10, Sex.MALE, G)
    f = score_item(T, ScoredItem.PULL_UP_OR_SIT_UP, 10, Sex.FEMALE, G)
    assert m != f  # 男引体向上 10 次与女仰卧起坐 10 次得分不同

def test_missing_value_returns_none():
    assert score_item(T, ScoredItem.VITAL_CAPACITY, None, Sex.MALE, G) is None

def test_value_worse_than_worst_segment_clamps_to_floor_not_none():
    # Ruling 17：差于表内最差档必须夹到该档分数，绝不可返回 None。
    # 返回 None 会把「极差成绩」当成「缺测」，既拉低 valid_count，又让该项
    # 不计入短板 W —— 最需要干预的学生反而被筛出红色层，且全程不报错。
    worst = segment_thresholds(T, ScoredItem.DISTANCE_RUN, Sex.MALE, G)[-1]
    at_worst = score_item(T, ScoredItem.DISTANCE_RUN, worst, Sex.MALE, G)
    beyond   = score_item(T, ScoredItem.DISTANCE_RUN, worst + 120.0, Sex.MALE, G)
    assert at_worst is not None
    assert beyond == at_worst

def test_value_better_than_best_segment_clamps_to_ceiling():
    best = segment_thresholds(T, ScoredItem.SPRINT_50M, Sex.MALE, G)[0]
    at_best = score_item(T, ScoredItem.SPRINT_50M, best, Sex.MALE, G)
    beyond  = score_item(T, ScoredItem.SPRINT_50M, max(best - 2.0, 0.1), Sex.MALE, G)
    assert at_best is not None
    assert beyond == at_best

def test_raw_from_score_roundtrips():
    for item in WEAKNESS_ITEMS:
        raw = raw_from_score(T, item, 80, Sex.MALE, G)
        assert abs(score_item(T, item, raw, Sex.MALE, G) - 80) <= 1

def test_domain_functions_are_pure_and_take_table_explicitly():
    # Ruling 15：同一个表对象传入两次结果必须一致，且 domain 不依赖任何全局加载状态
    a = score_item(T, ScoredItem.STANDING_JUMP, 230.0, Sex.MALE, G)
    b = score_item(T, ScoredItem.STANDING_JUMP, 230.0, Sex.MALE, G)
    assert a == b and a is not None
```

`app/domain/indicators.py`：枚举、`WEAKNESS_ITEMS`、`ITEM_BUCKET`、`AGE_GROUPS`、`age_group_of`，以及三个**首参为 `table`** 的纯函数。

**查表口径（Ruling 18，此前计划要求「线性插值」有误，已更正）**：国标评分表是**离散阈值表**，官方口径是「就低取档」，**不做插值**。插值会产出 `56/58/61/71/97` 这类国标里根本不存在的分数，使系统单项分与学校官方体测报表无法逐格对账——而 spec §12 黄金用例与 §1.3 可追溯性正是要拿真实报表校验的。

`score_item` 的算法：在 `table.segments[(item.value, sex.value, age_group)]`（按 `raw_value` 升序）内，从表推断方向，然后

- 越大越好：取**最大的 `raw_i <= value`** 对应的 `score_i`
- 越小越好：取**最小的 `raw_i >= value`** 对应的 `score_i`

**方向推断规则（Ruling 23，更正控制者原先给的 `scores[0] < scores[-1]`）**：只有当得分序列沿 `raw_value` 升序**全程单调不增**时才判为「越小越好」，否则判为「越大越好」。
原规则对 **BMI 是错的**：BMI 首末档得分为 80/60，按 `scores[0] < scores[-1]` 会误判为「越小越好」，得出 17.85→100、23.94→80，与国标正解相反。新规则对 **24 个单调组**（28 键 − 4 个 BMI 键）与原规则**完全等价**，只对 BMI 的 4 组不同且正是所需口径——BMI 走「越大越好」分支的「最大 `raw <= value`」，配合哨兵端点恰好复现国标的闭区间语义（15.0→80、17.85→80、23.94→100、24.0→80、28.0→60、38.0→60）。方向不硬编码，仍由表推断。阶梯查表无插值即无舍入。

**越界处理（Ruling 17，此前计划文本有误，已更正）**：`segments` 按原始值升序，故越界一律**夹到对应端点档位分**，不得返回 `None`：

```python
if value < low_raw:   return low_score     # 不是 None
if value > high_raw:  return high_score    # 不是 None
```

两端各返回哪一端的分数由表的单调性自动决定，实现无需判断该项是「越大越好」还是「越小越好」，也无需引用 `best`。

`None` **只**在两种情况下返回：`value is None`（真缺测）、或 `(item, sex, age_group)` 键不存在（调用方传错组合）。**「成绩差到落在表外」绝不是 `None`**——国标对低于最低档的成绩给最低分，返回 `None` 会把「极差成绩」误判为「缺测」，既拉低 `valid_count`（可能导致 `insufficient_data` 而完全不分层），又让该项目不计入短板 `W`，最终把体能最差的学生系统性地排除出红色层，且全程不报错。物理上不可能的读数（如 50 米跑 999 秒）由 Task 5 的清洗管道按 `indicator_ranges.yaml` 先行修正，不该由 `score_item` 兜。

`raw_from_score` 按 Interfaces 块所述做**方向感知的端点反查**（不插值，Ruling 22）；`segment_thresholds` 返回该组全部档位原始值阈值（升序），供边界测试取真实档位而非魔数，**键不存在时抛 `KeyError`**（Ruling：与 `raw_from_score` 对齐，避免调用方取 `[0]`/`[-1]` 时抛含义不清的 `IndexError`）。

`app/refdata.py`（**在 domain 之外**）：`DATA_DIR` 指向 `backend/data`；`load_standard(path=None)` 读 CSV 构造 `StandardTable`，文件不存在抛 `FileNotFoundError`；`standard()` 做进程内单例缓存——**缓存放这里，不放 domain**；`segment_count()` 供表完整性校验。

**domain 模块的注释与 docstring 里不要写出 `datetime.now`、`date.today`、`time.time` 这些 token**：`FORBIDDEN_CALLS` 是源码文本级子串匹配，写一句「本模块不得调用 datetime.now()」的合规说明反而会自伤红灯（Task 1 复审已登记此延后 Minor）。

| 字段 | 区间 | `non_positive_is_missing` |
|---|---|---|

| `weight_kg` | [35, 150] | `true` |
| `vital_capacity_ml` | [800, 9000] | `true` |

**为什么必须按字段区分、且必须在清洗层处理**：`score_item` 按 Ruling 17 对低侧越界做夹取，而夹取对「越小越好」的项意味着**低值得高分**。实测 `score_item(T, SPRINT_50M, 0.0, ...)` 与 `score_item(T, DISTANCE_RUN, 0.0, ...)` 都返回 **100 分**。`0` 是数值列最常见的缺测占位（NOT NULL 默认值、解析失败回退、导入空值填 0），而 50 米与耐力跑各占国标 20% 权重——一个体能最差的学生会因此拿到 40% 权重的满分，且 `speed_flexibility` 与 `endurance` 两个桶的短板同时消失。**这比高侧越界更危险，因为它抬分而非压分，不会被「成绩异常低」的直觉发现。**

不能在 `score_item` 里一刀切拒绝 `<= 0`：`strength_count = 0` 与 `sit_and_reach_cm < 0` 都是合法真实值。所以处置必须落在清洗层、按字段配置。

- [ ] **Step 4: 实现 `clean.py`**

超出区间的值**修正为最近的区间边界**并记 `outlier_corrected`（不丢弃整条记录，保留该生其余有效项）。

**但 `non_positive_is_missing: true` 的字段上，`value <= 0` 不走「修正为下界」，而是转 `None` 并记 `missing_dropped`**——这是 Ruling 21 的核心：把零填充占位识别为缺测，而不是当成一个极端好成绩。`strength_count` 仅在 `< 0` 时转 `None`（`0` 保留）。

`normalize_height`：`0 < cm < 3` 判定为米制，×100 后**四舍五入到 1 位小数**（Ruling 49：身高实测精度即 0.1 cm，且不舍入会留下 `1.68 → 168.00000000000003` 这类浮点残渣；身高经 BMI 参与国标计分，Ruling 18 的就低取档在档位边界上理论上可能被 1e-14 级误差翻档，舍入把这一类风险整体消掉），记 `unit_normalized`；`cm <= 0` 按上条转 `None`。去重键为 `(student_no, batch_key)`，保留后者。缺失字段保持 `None` 并记 `missing_dropped`——**绝不填 0**，因为 0 分会污染短板判定。

**空学号处置（Ruling 47）**：`student_no` 为空或全空白的记录**整条剔除**，记一条 `missing_dropped`、`field = "student_no"`、`processed_value = None`，且 `reason` 必须明写「整条记录无法归属，已剔除」而不是只说该字段缺失。理由：没有学号的记录无法归属到任何人，既不能入库也不能参与任何计算；而「缺失的标识导致整条记录被剔除」在语义上仍是 `missing_dropped`，`field` 列已足以指明缺的是哪一项，不需要为此新增第五个 `kind`（那会牵动 Task 3 已建的 CHECK 约束）。

**体成分同样要去重（Ruling 48）**：`clean_body_comp` 的去重键为 `(student_no, measured_on)`，保留后者，记 `duplicate_removed`——与 `clean_fitness` 同构。原计划只给了体测的去重键，属遗漏：`body_composition` 上有 `UniqueConstraint("student_id", "measured_on")`（Ruling 24），不去重会让 Task 10 的 upsert **静默覆盖**先前那条而不留任何痕迹，与体测路径的留痕行为不一致。

**绝不取均值**：同日两次测量取后者，不得取平均。两条测量的平均值是一个**从未被测量过的数**，那属于 Ruling 21/34 一脉相承禁止的凭空捏造；「后者覆盖前者」则对应「复测/更正以最后一次为准」这一可解释的口径。

**记录级条目的 `field` 取值（Ruling 50，已更正与 Ruling 47 的冲突）**：`field` 的取值分两类，不得混用——
- **`duplicate_removed` 是真正的记录级条目**：`field` 取导出常量 `WHOLE_RECORD = "*"`，两个值列放被丢弃行与保留行的日期（体测放 `tested_on`，体成分放 `measured_on`），便于追溯是哪两条撞了。常量须导出并被测试钉住，不得在多处硬编码 `"*"`。
- **空学号剔除仍取 `field = "student_no"`**（Ruling 47 更具体，优先）。理由：它并非「两条记录相撞」，而是「某个具体字段缺失导致整条记录无法归属」，`field` 指名缺失字段比写 `"*"` 信息量更大，且与其余 `missing_dropped` 条目的语义一致。记录级与否体现在「整条被剔除」这一后果上，由 `reason` 文字说明，不靠 `field` 表达。

- [ ] **Step 3: 实现潜变量模型（spec §10.2）**

```text
latent_fitness    ~ N(μ = cfg.latent_mean, σ = cfg.latent_sd)      # 缺省 N(0, 1)
latent_endurance  = 0.8·latent_fitness + N(0, sd = 0.6)
latent_strength   = 0.7·latent_fitness + N(0, sd = 0.7)
latent_speedflex  = 0.6·latent_fitness + N(0, sd = 0.8)

6 个短板判定项得分 = clip(70 + 15·latent_所属桶 + N(0, sd = 5), 0, 100)
BMI 得分           = 由身高体重分布独立生成后正查评分表
各项原始值         = raw_from_score(得分, 性别, 龄组) → 档内抖动（Ruling 54a/57）
```

**`N(0, x)` 里的 `x` 一律读作标准差，不是方差**（Ruling 73 澄清）。按方差读会让耐力/力量的理论相关系数从 0.57 掉到 0.46，叠上逐项噪声与国标档位离散化之后已经贴近「相关系数 > 0.4」那条断言的边界；按标准差读留出的是 0.50 左右的实测余量。`LATENT_LOADINGS` 的注释必须显式写「第二个数是 sd」。

**`cfg.latent_sd` 必须真正接进 `rng.normal`**（Ruling 66）：σ 硬编码成 `1.0` 会让 Task 9 只剩 μ 一个旋钮，而目标分层分布 20/45/35 的逼近需要两个自由度。二分法调参本身不在本 Task（属 Task 9）。


`latent_fitness` 的 μ/σ 由 `target_layer_dist` 反推：用二分法调 μ 使生成人群的红/黄/绿比例逼近目标。**该分布断言在 Task 9 落地**（需要分层引擎才能算），本 Task 只保证潜变量与得分生成正确。

- [ ] **Step 4: 实现两学年与三时点**

本学年 `week8`/`week16` 相对 `week1` 按实验班/对照班差异化演进——**该差异逻辑属 Plan 03**，本 Task 只做小幅随机漂移并预留 `intervention_effect` 参数位。

**上学年得分按 spec §6.3 的判定表反推注入（Ruling 62/63，承重）**

`trend_label` 不是装饰性标签，它是交给 Task 8 交叉验证、并驱动分层规则 Y4 的**真值**。四类按 `cfg.trend_mix`（`持续下滑 20%`、`波动大 15%`、`稳步提升 25%`、`稳定 40%`）用 `allocate_quota` 精确配额。记 `delta_i = 本学年得分_i − 上学年得分_i`（**正 = 进步**），总分变化按 spec §6.3 的口径：`Delta = national_total(curr) − national_total(prev)`，其中 `national_total(s) = (Σ 全部 7 项 w_i·s_i) // 100`（**先各自整除、再相减**，Ruling 71/76；`w_i` 取自 `ITEM_WEIGHTS`）。

构造顺序必须是「**先定上学年的 BMI 得分，再把它对 `Delta` 的贡献从目标里扣掉**」：BMI 的学年间变化来自身高体重自身的噪声与 `PREVIOUS_YEAR_WEIGHT_SHIFT`，不受趋势模型控制，而它占 15% 权重——一次 1.2 kg 的年度体重漂移就能贡献 ±3 分，足以把一个「稳定」学生推过 ±5 分线。故六项要承担的加权变化量是 `Delta_6 = Delta_target − w_bmi × delta_bmi / 100`。

四类的 `delta_i` 模式（全部为**整数**，且在 `prev_i = curr_i − delta_i ∈ [0, 100]` 的可行域内）：

| 标签 | 目标总分变化 `Delta_target` | 逐项模式 |
|---|---|---|
| `持续下滑` | `−U(6, 18)` | **均匀**：六项各承担约 `100·Delta_6 / 85` 分（85 = 六项权重和），叠一个**和为零**的逐项抖动（`|e_i| ≤ 3`） |
| `稳步提升` | `+U(6, 18)` | 同上；额外要求 `min_i delta_i > −5` |
| `稳定` | `U(−2, +2)` | 同上，抖动 `|e_i| ≤ 2`；额外要求 `#{i: delta_i ≤ −5} ≤ 2` |
| `波动大` | 不设目标 | 恰好 **3 项为正、3 项为负**，每项幅值 `~ U(10, 16)`；**正号给该生得分最低的三项、负号给得分最高的三项**（可行域余量最大） |

**均匀分配而不是按 `1/w_i` 反比分配**：国标总分是加权**平均**，要让总分动 `Delta` 分，最自然的形态是六项一起动约 `Delta` 分。按 `1/w_i` 反比虽然也能让加权和精确命中，但会让低权重项承担最大摆幅（`Delta_6 = −20` 时 w=10 的项要降 33 分、w=20 的只降 17 分），既不可行（`prev_i` 会冲出 100）也不像真实的整体衰退。

**必须「落档 → 重算 → 校正」，不能靠留余量（承重）**：`prev_i` 是「目标分经 `raw_from_score` 就低取档后 `score_item` 回读」的结果，而国标得分序列是 `100,95,90,85,80,78,…,62,60,50,40,30,20,10`——**60 分以下档距为 10 分**，就低取档单项最多吃掉 9 分、六项加权后最多约 7.65 分。这个损失与 `稳定` 类的 ±5 分窄带同量级，靠「把目标定得远一点」是躲不过去的。正确做法是把量化**显式化**：

1. 按上表抽 `delta_i`，算 `prev_target_i = curr_i − delta_i`；
2. **落档**：`prev_i = score_item(raw_from_score(prev_target_i))`，即不超过目标的最大官方档；
3. **重算**：用落档后的 `prev_i` 精确算出 `delta_i' = curr_i − prev_i`，以及 `Delta' = (Σ 全部 7 项 w_i·curr_i) // 100 − (Σ 全部 7 项 w_i·prev_i) // 100`。**必须是这个「先各自整除、再相减」的形式，不是 `Σ w_i·delta_i' / 100`**（Ruling 71）：后者是连续量、且与被判定实际使用的口径相差最多 1 分——`national_total()` 就是 `Σ w·s // 100`，所以两侧必须同口径。`稳定` 类的可行带只有 `[−4, +4]` 九个整数，1 分足以让生成侧与 oracle 侧判反。实测本数据里两种口径差值非零的有 **443/500 人**（区间 `[−0.90, +0.95]`），分类不一致 0 人——**0 是这份数据的运气，不是构造保证**，故口径必须写死。
4. **校正**：若 `Delta'` 未达该标签的判据，把**权重最大**的那一项的 `prev_target` 再朝目标方向推一个官方档（`持续下滑` 是 `+= 10`、`稳步提升` 是 `−= 10`、`稳定` 取能缩小 `|Delta' − Delta_target|` 的那一侧），回到第 2 步。每轮至少让 `Delta'` 朝目标移动 `w_max × 10 / 100 = 2` 分，故**单调且有界**（上限 8 轮）；超限则 `RuntimeError` 响亮失败，不得静默放行一个标签与数据不符的学生。`波动大` **不参与校正循环**，因为它的判据由构造保证（Ruling 77，更正原文那条永不执行的校正分支）：判据是 `max_i |delta_i'| ≥ 10`，而**正号的三项**满足 `prev_target = curr − m`（`m ≥ 10`）、就低取档只会让 `prev' ≤ prev_target`，于是 `delta_i' = curr − prev' ≥ m ≥ 10` **恒成立**——落档对正 delta 只增不减。所以 `max` 永远由正号那三项兜住，负号三项被落档缩小多少都无关。原文写的「落档后复核 `max|delta_i'|`，不满足就把幅值最大的那一项再往上推一个官方档」是一条**可证明永不执行**的分支，不得实现（实现了也测不到，属死代码）。符号分裂（恰好 3 正 3 负）同样由构造保证：负 delta 最多被落档缩小 9 分（60 分以下档距为 10），而幅值 ≥ 10 > 9，故符号不会翻。实测 500 人里 **19 人触发了校正、全部 1 轮内收敛、`RuntimeError` 0 次**，且触发者全是 `持续下滑` / `稳步提升` / `稳定` 三类。

**标签分配必须按可行域筛选（Ruling 70/78：判据是「逐项最小余量 + 符号纯度」叠出的 `Delta_target` 可行窗口，不是加权和，也不是四个孤立的阈值不等式）**：均匀分配下每一项都要动约 `100·Delta_6 / w_free` 分，所以卡住的是**最差那一项的余量**，加权和会给出假阳性。反例：`curr = (95,95,95,95,95,20)` 的加权和 `Σ w_i(100−curr_i) = 1925 ≥ 1800` **通过加权和判据**，但每项要降 21.2 分而那五项只有 5 分余量 → `prev_target` 冲到 105、校正推到表顶端点推不动 → `RuntimeError`。

实现形式是「每个学生 × 每个标签 → 一个可行的 `Delta_target` 区间（`None` = 该类对他不可行）」，由三个约束相交得出：

1. **名义区间**：该标签的 `delta_target_range`（上表的字面值）；
2. **逐项可行域**：`|Delta_6| ≤ w_free × (min_i 余量 − 抖动上限 − 校正预留) / 100`，其中 `余量` 对 `持续下滑` 取 `head_up = min_i(100 − curr_i)`、对 `稳步提升` 取 `head_down = min_i curr_i`、对 `稳定` 取两者较小值；`波动大` 则是 `min_i curr_i ≥ swing_max 且 max_i curr_i ≤ 100 − swing_max`（`swing_max` = 幅值上限 16，即计划表格里的 16/84）；
3. **符号纯度**：六项必须整体同号（`持续下滑` 全 ≤ −1、`稳步提升` 全 ≥ +1、`稳定` 无一项 ≤ −5）。**这一条是必需的而非锦上添花**：落档只会把 `prev` 往下拉、把 `delta_i'` 往上抬（最多 9 分），若初始 `delta_i` 本身就在 0 附近，抬过 0 之后就可能凑出「恰好 3 正 3 负」，被判定表的**第一行**（`波动大`）抢走标签——那时无论怎么调 `Delta'` 都命中不了自己的标签。`round()` 的半格余量（`round(x) ≤ k ⟺ x < k+0.5`）也要计进纯度边界。

**`波动大` 必须排除被表下溢出标记的学生**（Ruling 72）：被标记者的 `pull_up_or_sit_up` 由溢出逻辑固定为地板值，`delta ≡ 0`，而 spec §14 #23 明写 `delta_i = 0` 两边都不计入 → 最多 3 正 2 负 → `min = 2 < 3`，`波动大` 对这批人**结构性不可达**。不排除会让校正循环在他们身上必然失败。
**附带的分布后果（已知、暂不处置）**：`max curr ≤ 84` 对性别敏感（男 ≤84 占 54.5%、女 60.0%；男 p90 = 100、女 98），叠上 28 名男生被整条排除，`波动大` 实到 **28 男 / 47 女**（女生占 62.7%，而人群只占 45%）。规则 Y4 只看 `持续下滑`（其池性别比 40.7% vs 40.4%，平衡），故对分层分布的直接影响小。已列入延后 Minor 交终审。

配额分配顺序为「先 `波动大`（最受限）→ `持续下滑` → `稳步提升` → 余下全部给 `稳定`」，每类从自己的可行池里按 `allocate_quota` 的数量抽取（池内用 `rng.permutation` 打散），**任一池不足时响亮报错**（`ValueError`，报出需要数与实有数），不得静默改标签。实测顺序筛选后的池大小：`波动大` **260**/需 75、`持续下滑` **152**/需 100、`稳步提升` **318**/需 125、余下 200 人给 `稳定`（`稳定` 不可行 **0** 人）。**最紧的是 `持续下滑`（1.52×），不是 `波动大`（3.47×）**——Task 9 调 `latent_mean` 时先枯竭的是它（见前向约束）。被 Ruling 58 标记的学生，其 `pull_up_or_sit_up` 的 `delta_i` 由溢出逻辑固定（地板效应），趋势模型只在**其余五项**上分配（`w_free` 因此从 85 降到 75），且第 3 步的 `Delta'` 要把这一项的固定贡献算进去。

**`make_fitness_tests` 的记录循环必须拆成两趟**（Ruling 74）：第一趟整批算全部身高体重与 **BMI 得分**，第二趟才算六项。理由是第 3 步的「先扣 BMI 贡献」要求抽 `delta_i` 之前就知道上学年的 BMI 得分，而 BMI 得分档位只有 `{60, 80, 100}`，`delta_bmi` 可达 ±40、贡献 ±6 分——**超过 `稳定` 类的整个 ±5 带宽**，不先知道它就无法定标六项。

**上学年记录必须按上学年的年龄组查表（Ruling 56）**：即用 `age_group_of(age - 1)` 而非 `age_group_of(age)`。跨线学生的比例是 **26.4%**（500 人中 132 人，渐近值约 25%）——只有 `age == 20` 会跨 19/20 线，`age >= 20` 的 45% 里其余的人两学年同组（Ruling 61 更正：原文写的 45% 是 `age >= 20` 的比例，不是跨线比例）。缺陷仍是承重的：实测旧数据里 **334 / 2376 个上学年单元格（14.1%）**两张表给出不同得分（Ruling 67 更正：此前写的 1213/2376 = 51.1% 是把**修复后**数据在反方向的度量误当成了旧缺陷的量级，高估 3.6 倍），每项趋势被系统性低估约 0.83 分，而**趋势是分层规则 Y4 的唯一输入**，偏差会直接改变分层结果。反查生成上学年原始值时同样用上学年的龄组，保证正反查同表。

**原始值必须真实，不能全部落在档位端点上（Ruling 54）**：`raw_from_score` 按 Ruling 22 返回的是「仍能取得该分的**最差**原始值」，即档位端点。若直接采用，生成数据里每个原始值都恰好是国标表的阈值——例如所有肺活量都是 120 的整数倍、所有立定跳远都是 4 cm 的整数倍，一眼就是造的。两步修正：

1. **档内抖动（默认开启，`jitter_within_band: bool = True`）**：在**不改变所得档位**的前提下，于档带内向「更好」一侧均匀取值。越大越好项的档带是 `[raw_s, raw_{s+1})`，取 `[raw_s, raw_{s+1})` 内的均匀值（**不含**上界，否则会跨入下一档）；越小越好项的档带是 `(raw_{s+1}, raw_s]`，取 `(raw_{s+1}, raw_s]` 内的均匀值（**不含**下界）。取值必须在**该列的测量分辨率**上离散化（肺活量/立定跳远/次数 = 整数，50 米/坐位体前屈/耐力跑 = 0.1），且换算到整数单位后做，取完用 `score_item` 回验所得档位未变，并由测试逐档断言。次数类项目（引体向上/仰卧起坐）在整数单位方案下自动覆盖，不需要单独的取整分支。

   **抖动只在「档距 > 测量分辨率」处生效，且严禁生成亚分辨率值（Ruling 57，事实前提由 Ruling 59 更正）**。实测国标 24 组的档距分布：肺活量 男 120 / 女 40 ml；50 米跑 **最高 4 档 0.1 s、其余 15 档 0.2 s**（女生另有 2 档 0.3 s）；坐位体前屈 男 1.0 / 女 0.8 cm；立定跳远 男 4 / 女 3 cm；引体向上/仰卧起坐 **男处处 1 次** / 女 2 次（含 2 档 3 次）；耐力跑 5 s。因此 50 米跑在多数档位上**有**抖动空间（0.2 s 档距 vs 0.1 s 分辨率），实测 42.2% 的记录脱离了阈值；**男生引体向上处处档距 1 次 = 分辨率 1 次，恒不抖动**，它的真实缺陷是表下截断（见下条）。**明令禁止**为了制造抖动而生成 6.73 s 这类亚分辨率值：那会伪造出评分表根本没有的测量精度，与 §12「可与学校官方报表逐格对账」冲突；全部生成值必须仍是 `10^-MEASURE_DECIMALS` 的整数倍，并由测试把 `MEASURE_DECIMALS` 逐字钉死。

2. **表下溢出（可配，`sub_floor_rate: dict[str, float]`，键格式 `"<sex>:<item>"`）**：对真实人群中大量存在低于国标最低档的项，生成低于表内最低档的值。第一批**只对男生的 `PULL_UP_OR_SIT_UP` 开启，默认 10%**，取 `[0, 表内最低档原始值)` 内的整数；其余项默认 0%。理由：国标男生引体向上最低档是 5 次（大三大四 6 次），而真实高校男生 0–4 次占比很高；不生成这一段会让力量维度的低尾被截断，校内 P25 偏高、力量短板识别偏少、**红色层被系统性低估**，进而使 Task 9 的 20/45/35 分布断言难以达标。`score_item` 对表下值按 Ruling 17 夹到底档（10 分），与国标「低于最低档给最低分」的处置一致，故不需要额外打分逻辑。

   **溢出对象按「该桶潜变量最低的 `rate` 比例学生」选取，不按记录独立掷骰子（Ruling 58）**：取该性别全体学生按 `latents[sid][该 item 所属桶]` 升序排序（平手按 `student_id` 决胜），取前 `int(round(n × rate))` 名构成**该生的持久标记集合**；被标记者两学年六个时点的该项原始值一律落在表下区间，逐条重抽以体现测量波动。按记录独立抽样会造出「`latent_strength = +2` 的壮汉一个引体向上都做不起」以及「同一人 week1 做 12 个、week8 做 0 个」，两者都与潜变量模型直接冲突。未知键必须响亮 `ValueError` 并附合法键清单。

   **地板效应（Task 8/9 前向约束）**：被标记者该项得分被钉死在底档，故该项的学年间趋势恒为 0，趋势判定与黄金用例必须容忍。


**关于目标分层分布**：`latent_fitness` 的 μ/σ 反推（二分法逼近 20/45/35）**不在本 Task**——它需要 Task 9 的分层引擎。本 Task 只暴露 `latent_mean` / `latent_sd` 参数位并保证生成正确。**已知非线性**：实测 μ=0 时六个短板项的平均国标得分是 **67.5 而非 70**，因为国标低分区档距为 10 分、就低取档会系统性压低均值。Task 9 调 μ 时必须知道这一点，不能用线性外推。

- [ ] **Step 5: 实现 `sections.py` 编班（spec §10.3）**

**行政班数量必须由学生数反推，不得硬编码（Ruling 55，退化子句由 Ruling 60 更正）**：以「装得下所有人的最少班数」`ceil(n / section_size_max)` 为基准，**只有当把人数摊到 `teachers × sections_per_teacher` 个班上仍不低于 `section_size_min` 时**，才把班数抬到这个教师带班下限：

```python
count = max(1, ceil(n / high))
teacher_floor = max(1, teachers * sections_per_teacher)
if n // teacher_floor >= low:      # 抬到下限不会把班规模压穿下限，才抬
    count = max(count, teacher_floor)
```

再把学生尽量均分使每班落在 `section_size` 区间内；500 人 / 上限 38 → **14 个班**（每班约 35–36 人）。原计划写「12 个行政班」与「全员编入」「每班 30–38 人」互斥（12 × 38 = 456 < 500），spec §10.3 已同步勘误——指导文件的「2–3 名教师 × 每人 2 个自然班」说的是**阶段一的实验样本**（4–6 个班、约 120–228 人），不是 500 人的编班总数。

**不得写成无条件的 `max(ceil(n / high), teacher_floor)`（Ruling 60）**：那个字面公式在小规模下会**自己违反**它要满足的班规模区间——实测 n=120 给 6 个班、每班 20 人（而 `[30, 38]` 在 n=120 时是可行的，4 × 30 = 120），n=40 给 6 个班、每班 6.7 人。这与上一轮修掉的「12 × 38 = 456 < 500」是同一类算术错误，只是藏在退化分支里。带守卫的版本在 n=120 给 4 个班（每班 30，合规）、n=180 起与字面公式一致、n=500 同为 14。

当学生数太小以致 `[30, 38]` 区间**根本不可行**时（n < 30 × teacher_floor），退化为 `ceil(n / high)` 个班且**不施加班规模下限**（n=40 → 2 个班、每班 20 人，比 6 个班每班 6.7 人合理），并在 docstring 说明该退化；班规模断言的测试只在 500 人配置下运行。

阶段二另建 3 个 `stratified` 分层班（提升班/强化班/拓展班），**同一批学生全员二次编入**。注意 `stratified` 编班在本计划中按 `latent_fitness` 三分位近似分配即可——真实的按分层结果编班依赖 Task 9 输出，属计划 04 的阶段二功能。这也是 `make_sections` 需要接收 `latents` 参数的原因（该参数为必需、无退化缺省值，避免调用方漏传而静默得到错误分配）。

- [ ] **Step 3: 国标常模的推导口径（Ruling 84，不新增数据文件）**

国标 2014 公布的是**评分阈值**，不是人群百分位常模，所以「数值取自国标 2014 常模」无法照做。改为从仓内已有的 `national_standard_2014.csv` 按一个**显式假设**推导：

> **假设**：全国参考人群在该项原始值上**均匀分布于评分表的量程** `[lo, hi]`（`lo`/`hi` = `segment_thresholds` 的首末阈值）。
> **推导**：得分分布的第 `p` 百分位 = `score_item(table, item, lo + q/100·(hi − lo), sex, age_group)`，其中
> `q = p`（越大越好）或 `q = 100 − p`（越小越好）。

**方向感知是承重的，不是修饰**。50 米跑与耐力跑越小越好，原始值的低分位对应**高**得分；不做反向映射，这两项会得到 `P10=80 > P25=74 > P75=50` 这种**递减**序列，而 `PercentileRow` 的语义要求 `p10 ≤ … ≤ p75`，短板判定线（`score < p25`）于是彻底失效。方向**从表推断**（比较 `score_item(lo)` 与 `score_item(hi)`），不得按项硬编码——`indicators._lower_is_better` 已有同一套推断，但它是私有的，`percentile.py` 自己用公开 API 推一次，不要去 import 私有名。

`hit_rules` 的语义须在 docstring 里写清：**它是「本次求值评估过的规则序列」，最后一项即命中者**，而非「所有命中的规则」（命中即停意味着只可能命中一条）。保留已评估但未命中的前缀，是为了能回答「为什么这个学生不是红色层」——这是 spec §4.3 要求的可追溯性的一部分，也是 `explain()` 生成文案的依据。

`explain(result, derived)` 按 `hit_rules[-1]` 生成中文文案。**它能引用的证据只有 `DerivedResult` 实际携带的字段**（Ruling 126，更正原文的「短板项目名 + 校内百分位」）：

- **短板项目名**：`derived.weakness.items` 经 **`ITEM_DISPLAY_NAMES[item][derived.sex]`** 渲染成中文（Ruling 127；名称随性别变，男「1000 米跑」/ 女「800 米跑」）。
- **「低于校内同龄同性别 P25」是一个固定短语，不是数值**：`DerivedResult` **不携带** P25 的值（`WeaknessResult` 只有 `items` / `count` / `valid_count` / `dominant_bucket`）。spec §9.2:641 的示例文案本身也只写「低于 P25」而没有写具体数值，故不需要为了渲染它去扩 Task 8 的接口。若项目组日后要求展示具体百分位数值，那是 `WeaknessResult` 加字段的变更，须先改 spec §9.2。
- **体脂率数值与该性别阈值**：取自 `derived.body_comp.body_fat_pct` 与 `.limit`（Ruling 7 扩这两个字段就是为了这里）。`body_fat_pct is None` 时（体成分缺测）必须渲染成「体成分数据缺失，本次不参与判定（男生阈值 20%）」这类文案，**不得渲染成 `None%`**——`limit` 一律非 None（Ruling 97②）正是为此。
- **趋势与年均变化**：`derived.trend` 与 `derived.annual_change`。`annual_change == {}` 表示**无从比较**（不是「各项变化 0 分」，Ruling 99），文案不得渲染成后者。

**`StratResult.reason` 与 `explain()` 是两个不同的东西，不得互为副本**（Ruling 129）：`reason` 是**由 `RuleId` 单射得出的一行规范中文名**（例如 `R1` → 「短板 ≥2 项且体成分异常」），**不含任何学生数据**，供日志、API 与大屏列表使用；`explain()` 是**含具体数值的学生端长文案**。判据：`reason` 必须能只从 `RuleId` 算出来（`stratify` 里一张 8 行的映射表），若它需要读 `derived` 就说明职责串了。

**趋势对比取「每学年的 `week1`」，`years = 1.0`**（不是「`<= business_date` 的两条最新记录」）。理由：① spec §6.3 的「连续两次体测」在真实产品里就是**每年秋季那一次国标体测**，`week8` / `week16` 是学期内的过程测量（二次小测），归 spec §8.2 与 Plan 03；② 这正是 Task 6 的 `trend_label` 的口径（Ruling 75② 明写「趋势判据只在 week1 上由构造保证」），于是 Task 10 **白得一条端到端交叉验证**：**零注入下**（`dirty` 四项全 0）跑完管道后，`stratification_result` 反查出的趋势分布**精确等于** `{持续下滑:100, 波动大:75, 稳定:200, 稳步提升:125}`、`insufficient_data` **0 人**，分层分布 `red 0.22 / yellow 0.476 / green 0.304`（Ruling 149/153 补上原文漏掉的这个测量条件：该等式**不是无条件成立**，也不像 Ruling 146 一度裁定的那样「可证明为假」）。**缺省注入下它不成立**：4% 逐项缺测让 `national_total` 对 7 个计分项全有或全无地变成 `None`，500 人实测 209 人不可判、291 人可判里 280 人与 `trend_label` 一致（96.2%），故真不变量是**可判子集上的高一致率**，守卫是 `tests/integration/test_golden_cases.py::test_trend_agrees_with_the_generator_oracle_on_the_decidable_subset`；零注入那一组由 `tests/pipeline/test_daily.py::test_trend_matches_the_generator_oracle_on_week1_anchors` 守卫（60 人逐人对账 + 精确配额 `{持续下滑:12, 波动大:9, 稳步提升:15, 稳定:24}`）；③ 它让 Ruling 128 实测的分层分布（20.2/44.2/35.6 无线、22.0/47.6/30.4 有线）继续有效——那组数就是在 week1-vs-week1、`years=1.0` 下测的。
