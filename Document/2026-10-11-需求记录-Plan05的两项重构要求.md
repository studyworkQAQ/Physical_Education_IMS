## 二、控制者对影响面的清点（写 Plan 05 前必须先读这一节）

### R1 的影响面：**比看起来大，但不是推倒重建**

**⚠️ 好消息：Task 1 把设计令牌集中在了一个住址** —— `frontend/src/styles/tokens.css`（**110 个自定义属性**），四款字体在 `index.html` 的 Google Fonts link 里。故换肤的主战场是**那两个文件**，不是 42 个源文件逐个改。

**⚠️ 坏消息：有 5 处不是「换个变量值」就能改掉的**，它们是《田径场年鉴》这个方向的**结构性产物**：

| # | 结构性产物 | 为什么换色不够 | 影响 |
|---|---|---|---|
| 1 | **分道线母题**（`lane.css` + `LaneDivider.vue`）—— 粗线 3px `--ink` + 细线 1px `--track` 偏移 6px + 左端道次编号 | 它是**本设计的识别性来源**，被用在**每一个区块的分隔**上。「简洁」的方向下它大概率要**整体换成普通分隔线或卡片间距**，而不是改颜色 | `lane.css` 全文 + 全部用到 `.lane*` 类的组件 |
| 2 | **教师大屏是深底（`--ink`）** | 用户要「浅色系」→ **大屏要翻成浅底**。而 `tokens.css` 里三色语义各有 `--*-on-paper` 与 `--*-on-ink` **两个变体**，Task 3 专门实测过：深底上 26 对前景/背景对比度全过 4.5:1（最低 4.69），而**把 `--*-on-paper` 用在大屏只有 2.63–3.24**。翻成浅底要**重新做一遍对比度实测** | `teacher.css`、`Dashboard.vue`、`tokens.css` 的三色变体 |
| 3 | **纸张纹理**（`base.css` 的 `feTurbulence` 颗粒，opacity 0.035）+ 大屏底色的跑道弧 `radial-gradient` | 「简洁」通常意味着**去掉纹理** | `base.css` |
| 4 | **四款字体**：`Barlow Condensed`（数字，窄体无衬线，选它就是为了让数字看起来像**计时牌/成绩单**）+ `Noto Serif SC`（中文标题，宋体的笔画粗细对比给「年鉴/编辑部」的分量）+ `Noto Sans SC` + `JetBrains Mono` | 「简洁蓝白」通常配**无衬线的中性字体**，宋体标题与窄体数字都是「年鉴」味的一部分。⚠️ 但 `frontend-design` 技能明令禁止 Inter / Roboto / Arial / system-ui，也点名不要收敛到 Space Grotesk → **要另选一套既简洁又不落俗套的** | `index.html` 的 link + `tokens.css` 的 family 变量 + 所有写了 `font-weight: 800` 之类**为窄体调过的字重** |
| 5 | **出血布局与不对称网格**：学生端卡片故意出血到屏幕边缘（`margin-inline: -16px`）；大屏是 12 列但**故意让预警队列跨 5 列 / 分层分布跨 4 列 / 本周概览跨 3 列**（不是均分） | 「简洁」通常意味着**规整的网格与一致的间距** | `student.css`、`teacher.css`、`Dashboard.vue` 的 grid-template |

**⚠️ 还有一条 Task 2 报的待清扫会挡路**：`base.css:286` 的 `#a93623` 是**全仓唯一写在 `tokens.css` 之外的色值**（另有两处逐字重复的 `rgba(244,240,230,.35)`）。**换肤前要先把它们收进 `tokens.css`**，否则换完会漏。

**⚠️ 不要动的**：`present.ts`（**中文标签的唯一所有者**，141 个列名标签）、`catalog/resources.ts`（23 行资源目录）、`api/*`（客户端与 23 个手写 list 类型）、`smoke.mjs`（15 步 / 172 断言）。**换肤不该碰它们中的任何一个** —— 若碰了，说明改的不是皮肤而是结构，要停下来重新划分 Task。

**⚠️ 一个取证口径的连带**：Task 2/3/5 的 DOM 取证断言里含**真姓名/学号/班名**（不是写死的字符串），但也含**页面标题文字**（如「本周训练单」「ALERTS / LAYERS / THIS WEEK / CHECK-IN」）。⚠️ **大屏那几个是英文小标题**（`ALERTS` 等，为窄体全大写拉丁小标题设计的）→ **换成简洁方向后它们大概率要改成中文**，那会让 Task 5 的 147 条断言里的一部分变红。**这是预期的，但要按硬规矩 #88 先跑一次全量、把红的逐个收进来，不要只 grep 那个字符串。**

### R2 的影响面：**这是后端 + 前端的联合改动，比 R1 重**

**⚠️ 当前状态（实测）**：系统**没有登录、没有会话、没有密码**。身份是**两个请求头**：`X-Student-Id`（学生）与 `X-Teacher-Staff-No`（教师），前端用一个 `IdentitySwitcher.vue`（下拉选身份）+ `adoptFromUrl()`（`?student=4` / `?teacher=T0001` 深链接）代替登录页。

**这个取舍不是我偷工，是用户自己裁定的**：Plan 03 开工时用户说「项目只要能运行起来的原型系统就好」，故 Plan 03 的 Global Constraints 逐字写了「**刻意不做真实鉴权（用身份头 + 作用域闸门代替）**」。`app/api/deps.py:3-7` 也逐字声明了那两个头「**挡事故、不挡攻击**」。⚠️ **写 Plan 05 时不要把这条当成「之前的实现者偷懒」**，它是被裁定的范围；**但用户现在明确说它「有点太粗糙了」，故 Plan 05 要把它换掉。**

**要新增的东西（控制者的初步清点，写计划时要逐条实测复核）**：

1. **三张凭证表或一张带 `role` 的用户表** —— ⚠️ **今天 `student` 表有学号、`teacher` 表有工号，但都没有密码列**；**「管理员」这个角色今天在库里根本不存在**（`sys_user` 之类的表没有；`_MODELS_PUBLIC_BASELINE` 是 33、25 张表里没有用户/角色表）。**故这是 schema 变更**，会连带：`models/`、`_MODELS_PUBLIC_BASELINE`（33 → ?）、`_BATCH_OWNED_TABLES`、`init_db` 的 `create_all`、以及**架构守卫里那两条下界断言**（`len(real_py) >= 40`、`len(cases) >= 22` 之类，都是 `>=` 故加表不会红，但要实测）。
2. **注册与登录端点** —— 「学生通过学号注册」「教师通过工号注册」这两句**有两种读法**，⚠️ **Plan 05 开工前必须问用户**：
   - **(a) 自助注册**：任何人填学号 + 设密码就能成为学生（**那 `student` 表里已有的 60 行怎么办？谁都能claim 别人的学号？**）
   - **(b) 已有名册 + 首次登录时绑定密码**：学号必须已在 `student` 表里（由管理员或体测批次导入），注册只是「为这个已存在的学号设一个密码」
   - **控制者倾向 (b)**，因为 (a) 会让「学生 A 不能用 B 的身份头读写 B 的数据」那道作用域闸门（Plan 03 Task 1 建的）失去意义 —— **任何人都能注册成任何学号**。⚠️ **但这是产品口径，必须问，不要替用户定。**
3. **会话机制** —— ⚠️ **有一条硬约束**：后端 CORS 实测是 `allow_origins=["*"]` + **不带** `allow_credentials`（`app/main.py:184-189`），而**浏览器规范禁止 `*` 与 `credentials` 并存** → **cookie 会话方案要求先把 CORS 改成显式 origin 白名单**。故要么改 CORS，要么用 **Bearer token**（`Authorization` 头，不受 `allow_credentials` 限制）。**控制者倾向 Bearer token**（改动小、且今天的 `client.ts` 已经是「注入一个头」的形状，换成注入 `Authorization` 是一行）。
4. **密码存储** —— ⚠️ **不能明文**。需要 `passlib` / `bcrypt` 或 `argon2` —— **那是新依赖**，而 Plan 01–04 全程**零新增依赖**（`pyproject.toml` 从 Plan 01 起没动过）。**加依赖要按 Plan 02 的 P2-A8 那套先例办**（它加 pytest-cov 与 ruff 时立了完整口径：`requires` 与 `[dependency-groups].dev` 两处必须逐字同步，因为 pyproject.toml 有 sha256 指纹测试；且**生产依赖与 dev 依赖要分清** —— 密码哈希是**生产**依赖，不是 dev）。
5. **三种角色 × 页面归属的矩阵** —— ⚠️ **今天的路由是三条树 `/s/*`（学生 6 页）`/t/*`（教师 4 页）`/admin/*`（管理台 3 页）**，而**管理台今天不是「管理员」的，它是「教师」的**（9 个可写资源的 POST/PATCH/DELETE 全部挂 `require_teacher`，fix 波 1 加的）。**故「管理员」这个角色要接管什么，是一个需要裁定的产品问题**：
   - 管理台（23 个资源的增删改查）归管理员？还是教师也能用？
   - **教师端大屏与班级周报归教师**，学生端归学生 —— 这两条清楚。
   - ⚠️ **若管理台归管理员，那 9 个可写资源的 `require_teacher` 要改成 `require_admin`**，而这会连带 fix 波 1 加的那条遍历型守卫（`test_every_writable_resource_rejects_an_anonymous_mutation`）与那条全仓级断言（「可写的 9 个带 security、只读的 14 个不带」，钉住合计 **45**）。
6. **前端要加登录页与注册页** + 路由守卫（未登录跳登录、角色不符跳自己的首页）+ **`IdentitySwitcher` 与 `adoptFromUrl()` 要去掉或降级成开发工具**。⚠️ **`adoptFromUrl()` 是 Task 2/3/5 全部 DOM 取证的入口**（`?student=4` / `?teacher=T0001`）—— **去掉它，`smoke.mjs` 的第 14 步（13 条路由的 DOM 断言）就全废了**，要换成「先登录拿到 token、再注入」的姿势。**这是 Plan 05 里最容易漏的一格。**

**⚠️ 一条已有的安全事实要一起处理**：fix 波 2 查出 **`class_session.rpe_token` 曾对匿名调用方可读**（已修：从 `ClassSessionRead` 摘掉 + list 加 `list_exclude` + 新增教师身份的窄端点）。**但 48 个匿名 GET 里仍然包括 `GET /api/students`（60 人的出生日期）** —— 这在「原型、无鉴权」的口径下是被裁定的（终审也判定「今天的状态是诚实的，而且是被守卫钉住的诚实」），**但一旦引入登录，这些匿名 GET 就该逐个重新裁定**。**Plan 05 要有一节专门做这件事：48 个匿名 GET 逐个决定「登录后才可读」还是「仍匿名」。**
