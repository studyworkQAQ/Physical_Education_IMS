## 0. 本计划要解决的三件事

1. **库结构今天只能「删库重建」**：`init_db` 走 `create_all`，改模型没有迁移链。甲方现场升级版本时不能丢数据。
2. **生产档与演示档没有硬边界**：CORS 仍是 `allow_origins=["*"]`、登录没有限流与锁定、没有审计留痕、没有备份恢复、没有「一条命令起产品档」的部署入口。
3. **教师对「学生键资源」的泛型读是全校可读**：任教闸门只在大屏 / 周报 / 学生详情上，泛型 list/read 没有。教师账号之间没有数据隔离。

## 1. Task 1 —— alembic 基线迁移（唯一新增后端依赖）

- 引入 `alembic`（**本计划唯一新增的后端依赖**；用户已知情）。`alembic init`，`env.py` 从 `app.db.models` 的 `metadata` 取 `target_metadata`。
- **基线迁移**：对空库 autogenerate 出当前 **26 张表**的完整 DDL（含索引、唯一约束、外键）。⚠️ 基线迁移里**不要**带数据。
- `init_db` 改成：库不存在 → `upgrade head`；库存在且无 `alembic_version` 表 → **stamp 基线**（甲方手里的旧库就地纳管）；库存在且有头 → `upgrade head`。
- **可执行判据（本 Task 的核心）**：一条测试断言「`alembic upgrade head` 到空库后的 schema」与「`create_all` 的 schema」**逐表逐列逐索引一致**（用 `inspect()` 取两侧结构做规范化比较）。迁移对不对不靠人眼看 diff，靠这条。
- 测试库仍走 `create_all`（快），**但**那条一致性测试每跑一次全量就执行一次。
- ⚠️ 传导：`backend/requirements.txt` / `pyproject.toml` 加依赖后，**那个 sha256 指纹测试会红** → 按硬规矩 #88 先跑全量收进来、更新指纹。

## 2. Task 2 —— 迁移链纪律（改模型必须配迁移）

- 加一条守卫：在 `alembic` 的 head 上跑 `autogenerate --check`，**应当无 diff**（有 diff = 有人改了模型没写迁移）。挂进后端测试（用临时库）。
- 在 `CONTRIBUTING`/spec §13 点一句流程：改 `app/db/models/**` → 写迁移 → 该守卫绿。

## 3. Task 3 —— 登录限流与锁定

- 新表 `login_attempt`（`kind` / `login` / `ok` / `at` / 来源 IP 可选）；**不引 redis**（SQLite + 窗口查询够用，且零新依赖）。
- 规则（写进 `alert_rules.yaml` 同族的配置文件或 `app/auth/policy.py`，**阈值是配置不是代码**）：同一 `(kind, login)` 在 15 分钟内失败 5 次 → 锁 15 分钟；锁内再试回 **423**（或 429，二选一并写明）且 **message 不回显「还剩几次/是否 locked 于哪个账号」**（不给枚举信号）；成功登录清零。
- ⚠️ **与「不在册」与「验身不符」共用 code 的既有裁定不冲突**：限流是第三档，单独 code。
- 守卫：定点变异（去掉计数 / 去掉窗口）要红；并有一条「锁满后自动解锁」的时间注入测试（`now` 可注入，同 `run_daily` 的先例）。

## 4. Task 4 —— 生产档配置与启动自检

- `PE_ENV` ∈ {`dev`,`prod`}（缺省 `dev`）。`prod` 下：
  - CORS 从 `*` 改成读 `PE_CORS_ORIGINS`（逗号分隔白名单；**缺省空 = 不挂 CORSMiddleware**，即拒绝跨域）；
  - cookie 的 `Secure` 已仅在 prod 开（05A 既有），**加启动自检**：prod 下若 `PE_CORS_ORIGINS` 未设而代码仍要挂 `*`、或 `Secure` 未开 → **raise**（与 `demo.ps1` 那两道禁区守卫同姿势：失效方向必须是「起不来」，不是「静默不安全」）；
  - `PE_ALLOW_HEADER_IDENTITY` 在 prod 下**强制 0**（读到时是 1 也忽略，并打一条 warning）。
- 守卫：一条测试在 `PE_ENV=prod` 下断言上述三格；一条断言 dev 下行为不变（1340 条一条都不许红）。

## 5. Task 5 —— 请求审计留痕

- 新表 `audit_log`（`at` / `subject_kind` / `subject_id` / `staff_no` / `method` / `path` / `status` / `target` 可选）。
- 中间件**只记写操作与鉴权事件**（`POST/PATCH/DELETE` + login/logout/bind），**不记读**（体量与噪声）。
- 给管理员一个只读端点 `GET /api/audit-logs`（**仅 admin**）；管理台加一个只读页（**可后置到 Task 9**，本 Task 先有表 + 写入 + 端点）。
- 守卫：一次登录 + 一次写 → 两行审计；一次匿名读 → 0 行。
