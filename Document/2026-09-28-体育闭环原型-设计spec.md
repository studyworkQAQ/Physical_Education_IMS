## 1. 背景与目标

### 1.1 上游项目

指导文件立项的是一个教学实验研究项目：以现有乐跑体测系统为数据中枢，构建「数据驱动—智能处方—智慧反馈」闭环，把闲置的体测数据转化为个性化教学干预，并通过两阶段 RCT 验证其对大学生体质健康水平的提升效果。项目周期 2025.08–2027.08，技术开发节点为 2026-02-28。

指导文件 3.1.1 明确：「研究的核心不是从零开发新系统，而是如何基于现有乐跑体测系统，进行功能扩展和深度集成。」

### 1.2 本次交付物的定位

本次构建的是一个**可独立运行的原型系统，使用高保真仿真数据**，不接入生产环境。它同时服务三个目的：

1. **验证算法与教学流程** — 红黄绿分层模型、18 套处方模板匹配、三级预警规则是否自洽、可落地、可解释
2. **作为技术对接依据** — 与乐跑工程团队谈判时，用可运行的原型代替口头描述，明确接口契约与数据形状
3. **支撑成果展示** — 结题展示、专家评审、省内高校推广演示

因此原型必须在**算法科学性**与**可演示性**上达到生产级标准，而在**运维、鉴权、推送、多租户**等生产基础设施上明确降级。

### 1.3 成功标准

| 标准 | 来源 | 验收方式 |
|---|---|---|
| 单人处方生成 p95 < 3 秒 | 指导文件 2.2.1「3-5 秒内输出 4 周训练包」 | API 性能测试断言 |
| 500 人批量管道回放 < 60 秒 | 阶段二 N≈500 规模 | 集成测试断言 |
| 分层结果逐人可追溯至原始指标 | 研究可复现性要求 | 黄金用例测试 |
| 三级预警在仿真数据上均被实际触发 | 闭环完整性 | seed 数据质量断言 |
| 同一业务日期重跑结果字节级一致 | 教学实验期间数据纠错需求 | 幂等性集成测试 |

### 3.3 依赖方向（单向，不可逆）

```text
api → services → domain
              ↘ pipeline → adapters
db ← services / pipeline

domain 不依赖任何模块（叶子）
```

`domain` 必须是无 I/O、无数据库、无时钟依赖的纯函数层。这条约束是整个设计里最重要的一条：分层与处方是**研究结论本身**，必须能在没有任何基础设施的情况下被单元测试逐条验证，也才能支撑黄金用例与逐人追溯。

### 3.4 两个刻意的架构取舍

**前端单应用、两套路由树。** `/m/*` 学生端移动优先，`/screen/*` 教师大屏。共用 API client、类型定义与构建配置。大屏与手机只是视口和布局差异，不值得拆成两个工程。

**`http_lepao.py` 现在就建骨架**，即使没有一行真实请求。它定义「乐跑只读接口每日增量同步」的契约形状，配一组契约测试，且与 `MockLePaoAdapter` 跑同一套契约。接口字段一旦确定，改动只落在这一个文件，`pipeline` 与 `domain` 完全不动。这是指导文件 3.1.1「功能扩展与深度集成」的落点。

## 4. 数据模型

### 4.0 一个必须先钉死的口径

指导文件要求「对 8 项指标做校内百分位切分，低于 P25 的项目视为显性短板」。但 8 项指标方向不一致——50 米跑、1000/800 米跑越小越好，肺活量、立定跳远越大越好。直接对原始值算 P25 会得出相反结论。

**规定**：管道必须先把原始测量值按《国家学生体质健康标准（2014 年修订）》评分表转成 0–100 的国标单项得分（统一为越大越好），再在「同校区 × 同性别 × 同龄组」内计算百分位。指导文件中的「统一量纲」即指此步。同理，「肌肉量低于同龄 P20」的 P20 亦基于校内同龄同性别快照。

「8 项」的精确口径（8 项原始测量 → 7 个国标计分项 → **6 个短板判定项**，BMI 不计入短板）见 §4.2，该口径直接决定 `W` 的分母。

百分位**物化为快照表**而非实时计算：研究项目须能复现任意一天的分层结果，实时计算会随人群变动漂移。

### 4.1 组织与身份

| 表 | 关键字段 |
|---|---|
| `semester` | id、名称、起止日、教学周数(16)、是否当前 |
| `teacher` | id、工号、姓名 |
| `student` | id、学号、姓名、性别、出生年月、院系 |
| `course_section` | id、semester_id、teacher_id、课程名、上课时间、**`grouping_mode`** ∈ {`administrative` 阶段一班级内分层, `stratified` 阶段二跨班级重编班} |
| `enrollment` | semester_id × student_id × course_section_id（对应厦大「三自主」选课） |

阶段二的三个分层班（提升班 / 强化班 / 拓展班）作为独立的 `course_section` 记录存在，与行政班并存，同一批学生两套编班，用 `grouping_mode` 区分，演示时可切换。

### 4.2 学期节点数据（低频，来自乐跑）

| 表 | 关键字段 |
|---|---|
| `fitness_test_batch` | id、semester_id、**`timepoint`** ∈ {`week1`, `week8`, `week16`}、测试日期、来源、学年 |
| `fitness_test_result` | **`test_batch_id`**（指向 `fitness_test_batch`，**刻意不叫 `batch_id`**，见下）、student_id、8 项原始测量值、7 项国标计分项得分、总分、国标等级；`UniqueConstraint("test_batch_id", "student_id")` |
| `body_composition` | student_id、测量日期、肌肉量 kg、体脂率 %、骨骼肌指数、体重 kg、设备 |
| `interest_survey` | student_id、semester_id、填写日期、总分、各维度分、原始答题 JSON |

**`batch_id` 命名的安全约束（Ruling 31）**：本项目中「`batch_id`」一词专指**指向 `daily_sync_run` 的外键**，即幂等重放时 `delete_by_batch` 可以据以删除的归属键；只有派生表（`derived_metrics`、`stratification_result`、`percentile_snapshot`）才允许拥有该属性。指向其他父表的键必须用**可区分的名字**：`fitness_test_result.test_batch_id`（指 `fitness_test_batch`）、`cleaning_log.sync_run_id`（指 `daily_sync_run`，但该表按业务键 upsert、不按批删除）。

理由：若 `fitness_test_result` 也叫 `batch_id`，则误调 `delete_by_batch(session, FitnessTestResult, sync_run_id)` 时，因 `fitness_test_batch.id` 只有 1/2/3 而 `daily_sync_run.id` 按日递增，`sync_run_id ∈ {1,2,3}` 会**匹配上并静默删除真实源体测数据**——两列都是 int，外键与 `AttributeError` 都拦不住。命名区分把这一类错误变成响亮的 `AttributeError`。

**指标口径（重要，直接决定 `W` 的分母）**

指导文件反复使用「8 项指标」，指的是乐跑系统采集的 **8 项原始测量**：身高、体重、肺活量、50 米跑、坐位体前屈、立定跳远、引体向上（男）/1 分钟仰卧起坐（女）、1000 米跑（男）/800 米跑（女）。

但国标 2014 计分时**身高与体重合成 BMI 一项计分**，故实际**计分项为 7 个**：

| # | 计分项 | 单位 | 方向 | 国标权重 | 计入短板 W | 素质维度桶 |
|---|---|---|---|---|---|---|
| 1 | BMI（身高/体重派生） | kg/m² | 越接近正常越好 | 15 | **否** | 不入桶 |
| 2 | 肺活量 | mL | 越大越好 | 15 | 是 | `endurance` |
| 3 | 50 米跑 | s | 越小越好 | 20 | 是 | `speed_flexibility` |
| 4 | 坐位体前屈 | cm | 越大越好 | 10 | 是 | `speed_flexibility` |
| 5 | 立定跳远 | cm | 越大越好 | 10 | 是 | `strength` |
| 6 | 引体向上（男）/ 1 分钟仰卧起坐（女） | 次 | 越大越好 | 10 | 是 | `strength` |
| 7 | 1000 米跑（男）/ 800 米跑（女） | s | 越小越好 | 20 | 是 | `endurance` |

> **规定**：
> - **国标计分项 = 7 个**（含 BMI），用于计算国标总分、等级，以及 §6.1 空洞一所定的「综合评分」同层内排序。
> - **短板判定项 = 6 个**（**排除 BMI**），`W` 的分母是 6。排除理由：BMI 属身体形态，已由体成分维度 `C` 覆盖；若同时计入 `W` 与 `C`，一个体脂超标学生会被**重复计数**，导致 R1（W≥2 AND C）被系统性过度触发。
> - 指导文件原文「≥ 2 项 8 项短板」「8 项全达标」中的「8 项」，在本设计一律解读为上述 **6 个短板判定项**。此项属需求解读，列入 §14 待确认（#18）。
> - `valid_count` = 6 个短板判定项中有效（非缺失、未被剔除）的项数。

### 4.3 派生与分层（可追溯核心）

| 表 | 关键字段 |
|---|---|
| `percentile_snapshot` | semester_id、计算日、指标、性别、龄组 → P10 / P20 / P25 / P50 / P75、样本量、来源 ∈ {`school`, `national`} |
| `derived_metrics` | student_id、计算日、batch_id、各指标年均变化率 JSON、趋势标签、短板列表 JSON、短板数量 W、`valid_count`、体成分异常标记 C 与原因 |

`derived_metrics` 与 `stratification_result` 存的是**中间结果**，不是最终标签。任一学生的分层结果都能展开为：原始指标 → 国标得分 → 校内百分位 → 短板判定 → 命中规则 → 标签。

## 5. 数据流：每日批处理管道

指导文件 2.2.3 描述的对接流程为：每日自动同步课堂即时数据与学期节点数据 → 缺失值剔除 → 异常值修正 → 统一量纲 → 即时计算红黄绿分层标签 → 引擎调用预设模板自动匹配 4 周微周期运动处方。据此设计十阶段管道：

```text
 1 Extract     adapters 按业务日期水位线拉取增量
 2 Clean       缺失值剔除 → 异常值修正 → 国标得分换算（统一量纲）
               每一步写 cleaning_log
 3 Percentile  有新体测/体成分数据时，重算校内同龄同性别百分位快照
 4 Derive      年均变化率、趋势标签、短板列表、体成分异常 → derived_metrics
 5 Stratify    规则匹配 → 红/黄/绿 + 命中规则 → stratification_result
 6 Prescribe   ★ 仅对触发条件成立的学生生成（见 5.2）
 7 Aggregate   聚合 RPE / 打卡 / 二次小测，计算标准化得分
 8 Alert       三级预警规则求值 → alert → notification
 9 Weekly      每周日生成 weekly_class_report 与学生本周训练单
10 Commit      整批单事务 + 写 daily_sync_run
```

### 5.1 幂等性

以 `(semester_id, business_date)` 为幂等键。重跑时先删除该业务日期产生的派生数据（带 `batch_id` 的 `derived_metrics` / `stratification_result` / `prescription` / `alert`），再重算；原始数据按业务主键 upsert。

这使「某天数据错了，修完重放」成为安全操作——教学实验期间这一定会发生。

### 5.2 处方生成的五个触发条件

**处方不是每天重新生成。** 指导文件要求 4 周微周期，天天重发会把周期切碎、`week_deltas` 递进曲线失效。

生成触发条件仅以下五种：

1. 学生首次产生分层结果
2. 分层标签发生变化（如 黄 → 红）
3. 当前处方 4 周到期
4. 学期末体测/体成分数据刷新
5. 教师手动请求重新生成

而**分层重算、反馈聚合、预警求值是每天跑的**。这个频率差异必须显式区分，否则闭环会在第二天就乱掉。

## 6. 数据驱动层：红黄绿分层引擎

### 6.1 指导文件的三处规则空洞与本设计的补齐

指导文件 2.2.1（1）给出三色定义，但存在三处未定义，本设计补齐如下。**三项均标注为待项目负责人确认**（见 §14）。

**空洞一：「综合评分」从未定义。** 原文写「综合评分后，模型实时输出三色标签」，但三色定义里只出现短板数量与体成分，无任何评分参与。

> **规定**：分层判定用**纯布尔决策表**，不用加权评分。原文的三色定义本身就是布尔规则，加权评分反而不可解释、不可审校、无法单测。「综合评分」直接复用国标总分（0–100，本来就有），仅用于**同层内排序**（进步榜、教师关注优先级），不参与分层判定。

**空洞二：「历史趋势」被计算但从未被使用。** 原文把趋势列为三个变量之一并定义了三种轨迹，但三色规则里完全没提到它。

> **规定**：趋势**只作为升级修正项，永不降级**。字面判定为绿、但趋势为「持续下滑」的学生，升为黄（规则 Y4）。这符合原文「动态分层」与「直接升级为干预优先级」的一贯表述。

**空洞三：`短板 ≥ 2 且 体成分正常` 无归属。**

| 短板数 W | 体成分异常 C | 原文判定 |
|---|---|---|
| W ≥ 2 | 是 | 红 |
| W = 1 | 是 / 否 | 黄 |
| W = 0 | 是 | 黄 |
| W = 0 | 否 | 绿 |
| **W ≥ 2** | **否** | **⚠️ 未定义** |

该组合在真实数据中必然出现（如耐力、力量双短板但体脂率正常的瘦弱学生）。

> **规定**：归**黄**（规则 Y3），因体成分正常意味着代谢风险不高；另增设 **R2：W ≥ 4 时无条件升红**，短板过多本身即高风险信号。

### 6.2 完整决策表

按优先级自上而下匹配，**命中即停，所有命中规则 ID 写入 `stratification_result.hit_rules`**：

| # | 条件 | 标签 | 干预强度 |
|---|---|---|---|
| R1 | W ≥ 2 AND C | 🔴 red | 高强度、复合干预 |
| R2 | W ≥ 4 | 🔴 red | 高强度、复合干预 |
| Y1 | W = 1 | 🟡 yellow | 中等强度、重点突破 |
| Y2 | W = 0 AND C | 🟡 yellow | 中等强度、重点突破 |
| Y3 | W ≥ 2 AND NOT C | 🟡 yellow | 中等强度、重点突破 |
| Y4 | W = 0 AND NOT C AND 趋势 = `持续下滑` | 🟡 yellow | 中等强度、重点突破 |
| G1 | W = 0 AND NOT C | 🟢 green | 维持与兴趣拓展 |
| — | `valid_count` < 4 | ⚪ insufficient_data | 不分层，进异常名单 |

### 6.3 三个输入变量的精确定义

**① 短板判定 W**

```text
8 项原始测量（身高、体重 + 6 个测试项）
  → 国标 2014 评分表 → 7 个计分项得分（0–100，越大越好；身高体重合成 BMI）
  → 剔除 BMI（已由体成分维度 C 覆盖，避免重复计数）→ 6 个短板判定项
  → 在「同校区 × 同性别 × 同龄组」percentile_snapshot 中查该项 P25
  → 单项得分 < P25 记为显性短板
  → W = 短板计数（分母为 valid_count 个有效项，valid_count ≤ 6）
```

单项缺失时该项不计入 W，**绝不当作 0 分**。同时记录 `valid_count`；`valid_count < 4` 者本日不分层，标记 `insufficient_data`。

**② 体成分异常 C**

```text
C = (体脂率 > 男 20% / 女 28%)  OR  (肌肉量 < 同龄同性别 P20)
```

骨骼肌指数入库但第一批不参与判定（原文判定条件只用了体脂率与肌肉量）。

**③ 历史趋势**

回溯连续两次体测（**因此仿真数据必须生成两学年体测**），按国标得分计算年均变化率：

| 标签 | 判定 |
|---|---|
| `持续下滑` | 总分下降 ≥ 5 分 **或** ≥ 3 项单项得分为负变化 |
| `波动大` | ≥ 3 项变化方向不一致 **且** 存在单项绝对变化 ≥ 10 分 |
| `稳步提升` | 总分上升 ≥ 5 分 **且** 无单项下降 ≥ 5 分 |
| `稳定` | 以上皆不满足 |
| `insufficient_data` | 无历史体测（如新生）；不触发 Y4 |

### 6.4 主导短板

短板按素质维度归三桶（映射见 §4.2 表）：`endurance` / `strength` / `speed_flexibility`。

- **主导短板 = 短板数最多的桶**
- 并列时取**该桶内最低单项得分**者
- W = 0 时取**相对最弱桶**（即使全达标也有相对强弱），用于决定绿色层的兴趣拓展方向

## 7. 智能处方层

### 7.1 18 套模板的维度构成

`层(3) × 主导短板(3) × 体成分(2) = 18`，与指导文件「按层×短板×体成分预制 18 套」字面一致。

**已知事实**：按 §6.2 决策表，绿色层必然 `NOT C`，因此 `(green, *, abnormal)` 这 3 套**当前不可达**。

> **规定**：保留为**预留位**，不删除。理由：① 维持指导文件「18 套」的字面完整性，专家评审时无需解释为何只有 15 套；② 分层规则未来若调整（例如允许「8 项达标但体成分异常」者留在绿色层做体成分专项干预），模板位已就绪。生成器对这 3 套标记 `reachable: false`，不参与匹配。

### 7.2 模板 YAML 骨架

每套模板一个文件，体育专家可独立审校。**`review.status != approved` 的模板拒绝用于生成。**

```yaml
template_id: RED-END-ABN-01
version: 1.0
layer: red                      # red | yellow | green
weakness: endurance             # endurance | strength | speed_flexibility
body_comp: abnormal             # normal | abnormal
reachable: true
review:
  status: pending               # pending | approved
  reviewer: null
  reviewed_at: null
microcycle_weeks: 4
weekly_frequency: 4             # 红 4 / 黄 3 / 绿 2（指导文件原文）
sessions:
  - day: 1
    focus: 耐力
    blocks:
      - exercise_ref: interval_run
        impact_level: high      # 供安全后置处理识别
        intensity: {type: hrmax_pct, low: 60, high: 70}
        structure: {sets: 4, work_min: 3, rest_min: 2}
      - exercise_ref: compound_circuit
        impact_level: medium
        intensity: {type: onerm_pct, value: 70}
        structure: {rounds: 3, reps: 10}
progression:
  week_deltas: [1.00, 1.05, 1.10, 0.85]   # 第 4 周减量，超量恢复
addons:
  - when: body_fat_over
    module: energy_expenditure_plus_10pct  # 红层 +10% 能量消耗
  - when: muscle_low
    module: resistance_priority
```

指导文件给出的层级参数已全部落入模板：红层每周 4 天、耐力短板 60–70% HRmax 间歇跑、力量短板 70% 1RM 复合循环、体脂超标追加 10% 能量消耗模块；黄层每周 3 天、耐力短板持续跑+台阶训练、力量短板自重+弹力带抗阻、体脂偏高附加 5min HIIT；绿层每周 2 天、兴趣球类/定向越野/功能性训练 + 可选挑战任务。

### 7.3 装配器（`assembler.py`）

输入「学生档案 + 模板骨架」，输出 4 周训练包：

| 步骤 | 逻辑 |
|---|---|
| 1. HRmax | 优先用实测值；无实测则用 **Tanaka 公式 `208 − 0.7 × 年龄`**（比 `220 − 年龄` 在青年群体更准；公式可配置切换） |
| 2. 目标心率区间 | 模板给百分比 → 装配为个体绝对 bpm 区间 |
| 3. 周训练总量 | 模板基准量 × 个体修正系数（按性别 + 当前耐力国标得分分三档） |
| 4. 4 周递进 | 套用 `progression.week_deltas` |
| 5. 动作视频二维码 | 从 `exercise` 表取 URL 填入 |
| 6. 快照 | 全部输入输出写入 `prescription.assembly_snapshot`，保证可复现 |

### 7.4 安全后置处理器（`safety.py`）

独立模块、独立单测，**优先级高于模板定义**：

| 触发条件 | 处理动作 |
|---|---|
| BMI > 30 | 跑量按映射表下调；所有 `impact_level: high` 动作 → 查 `exercise_equivalence.yaml` 换低冲击等价动作 |
| 肌肉量 < 同龄同性别 P10 | 同上，并提高抗阻模块比重 |
| 体脂率异常 | 追加模板 `addons` 中的能量消耗模块 |

每次替换记录：原动作、新动作、触发条件、**映射表版本号**，写入 `prescription.safety_substitutions`。

**安全规则命中但映射表找不到等价动作时，不静默跳过**：生成 `warning` 级日志，处方状态置 `needs_review`，教师端标记「需人工复核」。宁可不自动，也不要自动错。

### 7.5 教师覆盖（`override.py`）

- 可调整：周训练天数、替换单个动作、调整强度档位、整体降量/加量、暂停处方
- 覆盖**不修改模板**，只在 `prescription` 上叠加 override 记录（原值 / 新值 / 理由 / 教师 / 时间）
- 下次自动生成时**回到算法基线、不继承覆盖**，但界面提示「该生上次存在人工覆盖」
- 所有覆盖进入统计，学期末可回答「教师在哪些环节最不信任算法」——这本身就是指导文件难点 3.2.1「平衡自动化推荐与教师人工干预」的研究数据

## 8. 智慧反馈层

### 8.1 三源采集

**课堂端 RPE（0–10 主观疲劳）**

教师在课次页点「发起课堂快评」→ 该课次对所有选课学生开放 → 学生端首页出现待办卡片 → 滑块打分 → 提交。记录**提交耗时**（指导文件要求 10 秒内完成）。教师端实时显示已提交/未提交名单，可现场催交。

不做扫码签到：H5 调摄像头权限复杂，且原型阶段学生已登录并绑定教学班。**已知局限：无法防代填**，真实上线时需回到乐跑 App 的实名环境。

**课外端每日打卡**

字段严格按指导文件：是否完成、完成时长（分钟）、自评感受三选一（轻松/适中/吃力）。

打卡窗口 = 当日 00:00–22:00。22:00 后提交仍入库但标记 `late = true`，**不计入当日完成**——完成率是 RCT 关键过程指标，必须严格。

指导文件存在一处内部矛盾：处方规定红层每周练 4 天、黄层 3 天、绿层 2 天，但同时要求「每晚 22:00 前完成今日训练打卡」，激励策略又写「连续打卡 7 天点亮自律达人徽章」。

> **规定（折中方案）**：每日都可打卡，**非训练日一键「今日休息」**；但**完成率只按处方训练日计算**。既支持「连续打卡 N 天」的激励语义，又不让绿层学生被无意义的每日打卡骚扰，训练日完成率作为 RCT 过程指标也干净。

**阶段端二次小测（每两周）**

项目：30 秒深蹲（次数）+ 20m 折返跑（秒），指导文件「或其他」→ 允许教师从测试项库中选组合。系统按学期周历自动算出应测周次（偶数周），教师确认并批量录入（按教学班列出学生逐个填）。

两个指标方向相反，须各自转成「越大越好」的**标准化得分**后再参与预警与进步榜计算：

```text
深蹲得分   = 深蹲次数（越大越好，直接用）
折返得分   = 该教学班内折返秒数的百分位反查（秒数越少 → 得分越高）
小测综合分 = 两项标准化得分等权平均
```

### 8.2 预警规则

阈值全部存于 `data/alert_rules.yaml`（带版本号），改阈值走版本控制而非改数据库。

| 级别 | 规则 ID | 条件 | 作用域 | 动作 |
|---|---|---|---|---|
| 🔴 | `RED_MINITEST_DROP` | 连续两次二次小测下降 ≥ 5% | 学生 | 教师端弹「降量建议」→ 教师点击 → 推送「减量 20%」 |
| 🔴 | `RED_RPE_SUSTAINED` | RPE 连续 ≥ 9 分 | 学生 | 同上 |
| 🟡 | `YELLOW_CHECKIN_GAP` | 打卡中断 2 天 | 学生 | **自动**发「补练提醒」，无需教师介入 |
| 🟡 | `YELLOW_CLASS_RPE_HIGH` | 课堂 RPE 均值 > 7 分 | **班级** | 教师端提示「调整强度」 |
| 🟢 | `GREEN_MASTERY` | 本周完成度 100% AND 二次小测提升 | 学生 | 生成电子勋章记录 |

指导文件给了阈值但未给判定口径。按运动干预「宁可早报」原则补齐如下（**四项均待确认**，见 §14）：

| # | 模糊点 | 规定 |
|---|---|---|
| 1 | 「RPE 连续 ≥ 9 分」的连续是几次 | **连续 3 次课堂快评**（约 1.5 周课次） |
| 2 | 「连续两次二次小测下降 ≥ 5%」如何计算 | 需 **3 个数据点**：`score(t) < score(t-1) × 0.95` **且** `score(t-1) < score(t-2) × 0.95`。首次可能触发于第 6 周 |
| 3 | 「打卡中断 2 天」 | 连续 **2 个应打卡训练日**未打卡（休息日不计入中断） |
| 4 | 「二次小测提升」（绿色激励） | 任一指标改善 ≥ **3%**。与下降阈值 5% 刻意不对称——正向激励应更宽松，让学生更容易拿到 |

### 8.3 消息通知

原型不做真实推送（需微信订阅消息资质 / 短信通道）。设计与 `DataSourceAdapter` 同构的可替换通道：

```text
NotificationChannel（接口）
├── InAppChannel             当前：写 notification 表，H5 红点 + 消息中心
├── WechatSubscribeChannel   未来：骨架 + 契约测试
└── SmsChannel               未来：骨架 + 契约测试
```

「一键推送减量 20%」「自动发补练提醒」在原型中落地为站内消息。换实现只动一个文件。

### 8.4 周周微调 —— 处方骨架与周微调两层拆分

指导文件要求「每周生成班级微调报告，学生即收到更新后的训练单」，但处方是 **4 周微周期**。每周重发整个处方会切碎微周期、使 `week_deltas` 失效。

> **规定**：拆成两层。

```text
prescription        4 周骨架，生成后不变（除非触发 §5.2 五个条件之一）
weekly_adjustment   每周一条微调记录：周次、调整系数、原因、来源(auto/teacher)

学生端「本周训练单」 = 骨架第 N 周 × 本周调整系数
```

「周周微调」与「4 周微周期」由此同时成立：微调改的是**本周训练量**，不是重开周期。预警触发的「减量 20%」落成一条 `weekly_adjustment(系数 0.8, 原因 RED_RPE_SUSTAINED)`，可追溯、可回滚。

### 8.5 班级微调报告

每周日批处理生成 `weekly_class_report`，内容：

- 红黄绿分层分布 + 周环比流动人数（升入/降出各层的人数与名单）
- 本周人均 RPE 曲线 + 与上周对比
- 按层分组的打卡完成率
- 二次小测进步榜 Top10 与退步名单
- 预警汇总（红/黄/绿各若干，已处理/待处理）
- **算法建议**：基于 `YELLOW_CLASS_RPE_HIGH` 等班级级信号，给出「本周建议整体降量/加量 X%」

```text
└──────────────────────────────────────────────────────┘
```

支持**自动轮播模式**（投屏用，每 15 秒切换主区块）与**手动模式**（教师课堂操作）。

**指导文件内部矛盾**：大屏「异常名单」阈值（连续 **3** 天未打卡、RPE > **8**）与预警规则（中断 **2** 天、RPE 连续 ≥ **9**）不一致。

> **规定：两套并存，职责不同。** 预警是需要教师处理的**正式工单**（阈值严、有处理流程与状态机）；大屏异常名单是课堂即时扫视用的**宽松筛选器**（阈值松、只展示不派单）。本条须在评审材料中主动说明，避免被追问。

### 9.2 学生端 H5（`/m/*`）

指导文件要求：本周完成度环形进度条、与同层均值对比柱状图、下一周训练重点提示一键推送。

| 页面 | 内容 |
|---|---|
| **今日** | 本周完成度环形进度条 · 今日训练卡片（动作列表 + 视频二维码 + 目标心率区间）· 快速打卡 · 课堂快评入口（有则显示）· 未读消息红点 |
| **我的处方** | 4 周微周期视图（当前周高亮）· 动作详情 · **本周微调说明**（为什么这周降量了） |
| **我的数据** | 7 项国标计分项雷达图（含得分与校内同龄同性别 P25/P50 参照线）· 我的分层标签（**可展开命中规则**）· 与同层均值对比柱状图 · 体成分 · 历史趋势 · 二次小测折线 |
| **消息中心** | 补练提醒 · 降量通知 · 下周训练重点 |
| **打卡** | 是否完成 / 时长 / 自评感受三选一；非训练日一键「今日休息」 |

**分层可解释性展开**（指导文件未要求，本设计新增）：分层标签可点击展开命中规则，例如「红色层 ← 你的 1000 米跑与引体向上在校内同龄男生中低于 P25，且体脂率 22.4% 超过男生 20% 阈值」。

理由：学生看到「红色层」的第一反应是焦虑甚至抵触，标签本身没有说服力；能展开看到具体依据才可能转化为动机，也才对得起指导文件「激发运动兴趣」的目标。代价是一个组件 + 一套文案模板。

## 10. 仿真数据生成器

### 10.1 数据规模

| 数据集 | 规模 |
|---|---|
| 体测（两学年 + 第 1/8/16 周三时点） | ~2,500 条 |
| InBody 体成分 | ~1,500 条 |
| 兴趣量表问卷 | ~1,000 条 |
| 每日打卡 | ~56,000 条 |
| 课堂 RPE（每周 2 课时） | ~16,000 条 |
| 二次小测（8 次） | ~4,000 条 |
| **合计** | **~80,000 行** |

### 10.2 核心手法：潜变量驱动

直接对各指标独立随机生成会得到现实中不存在的体质画像（耐力极差但力量极强的人比例失真）。真实体质是相关的，故用潜变量驱动 7 个国标计分项：

```text
latent_fitness    ~ N(0, 1)                    整体体质潜变量
latent_endurance  = 0.8·latent_fitness + N(0, 0.6)
latent_strength   = 0.7·latent_fitness + N(0, 0.7)
latent_speedflex  = 0.6·latent_fitness + N(0, 0.8)

6 个短板判定项得分 = clip(70 + 15·latent_所属桶 + N(0, 5), 0, 100)
BMI 得分           = 由身高体重分布独立生成后正查评分表
各项原始值         = 国标 2014 评分表反查(得分, 性别, 年龄组)   ← 分段函数线性插值
```

生成顺序为**先定目标分层分布，再反推潜变量参数**：设定 红 20% / 黄 45% / 绿 35%（**可配置，属研究设计参数，待确认**，见 §14），调 `latent_fitness` 的 μ/σ 逼近它。这样三层都有足够样本，不会出现「500 人全是绿色层」。

### 10.3 人口学与编班

- 500 人，男女比例默认 男 55% / 女 45%（可配），年龄 18–22
- 阶段一：**行政班数量由学生数与班规模上下限反推**（`ceil(n / 38)`，再微调使每班落在 30–38 人；500 人 → **14 个班**），其中 4–6 个班由 2–3 名教师带
- 阶段二：同一批学生另建 3 个 `stratified` 教学班（提升班 / 强化班 / 拓展班）
- 两套编班并存，演示时用 `grouping_mode` 切换

> **勘误（Ruling 55）**：本节原写「12 个行政班（每班 30–38 人）」，与「全员编入」「每班 30–38 人」互斥——12 × 38 = 456 < 500，装不下。指导文件原文的「2–3 名教师 × 每人 2 个自然班」描述的是**阶段一的实验样本**（4–6 个班、约 120–228 人），不是全部 500 人的编班总数；500 人是**阶段二**的规模。故行政班总数必须由学生数反推，不得硬编码。

### 10.4 体成分

- 体脂率：男 ~N(18, 5)、女 ~N(26, 6)，与 `latent_fitness` 负相关
- 肌肉量：与身高、体重、`latent_strength` 正相关
- 骨骼肌指数 = 肌肉量 / 身高²
- 校准到约 30–40% 学生触发体成分异常（男 > 20% / 女 > 28% / 肌肉量 < P20）

### 10.5 两学年体测

指导文件要求「回溯连续两次体测」算年均变化率，故须生成两学年数据：

```text
上学年得分 = 本学年得分 − 趋势项
趋势项按「持续下滑 / 波动大 / 稳步提升 / 稳定」四类按配置比例注入
```

### 10.6 过程数据须体现干预效果

否则 RCT 闭环无法验证：

| | 实验班（分层教学） | 对照班（传统教学） |
|---|---|---|
| 打卡完成率 | ~85% | ~65% |
| 课堂 RPE | 集中在 5–7 | 分散 4–9 |
| 二次小测 | 逐周改善 | 基本持平 |

### 10.7 刻意注入脏数据

这是「高保真」最容易被忽略的部分，也是清洗管道的测试素材。真实乐跑数据必然包含这些：

| 类型 | 比例（可配） | 例子 |
|---|---|---|
| 缺失 | 3–5% | 体测某项未测、体成分未测 |
| 异常值 | ~0.5% | 50 米跑 3.2s、体脂率 62%、身高 235cm |
| 量纲错误 | ~0.3% | 身高录成 1.75（米）而非 175（厘米） |
| 重复记录 | ~1% | 同一天两条打卡 |

### 10.8 可复现性

所有随机数由单一 `--seed` 驱动（默认 `20250828`，即指导文件填表日期）。同 seed 生成的数据字节级一致——演示可复现、bug 可重现，这对研究项目是硬要求。

生成器支持两种输出模式：写 `backend/data/seed/*.csv`，或直接入库。

### 10.9 外部依赖：体育学习兴趣量表版本

指导文件提到「体育学习兴趣量表」但未给量表版本。生成器先用占位结构（5 维度 × 5 点李克特：运动乐趣、运动能力自信、健康认知、同伴互动、教师评价），**须由项目负责人提供实际使用的量表**（见 §14）。

## 11. 错误处理策略

三类问题，三种原则。

### 11.1 A 类：数据质量问题（预期内、高频）

**原则：不抛异常、不中断批次**，记录到 `cleaning_log` 后继续。

| 情况 | 处理 |
|---|---|
| 单项缺失 | 该项不计入 W（**绝不当作 0 分**），记录 `valid_count`；`valid_count < 4`（共 6 个短板判定项）者本日不分层，标记 `insufficient_data` 并进异常名单 |
| 异常值 | 按 `data/indicator_ranges.yaml` 合理区间判定 → 超出则修正为区间边界或标记剔除 |
| 量纲错误 | 启发式检测（如身高 < 3 → 判定为米制，× 100） |
| 重复记录 | 按业务主键去重，保留较新者，写 `duplicate_removed` |

`valid_count < 4` 的设计原则：**宁可不出结果，也不要出一个错的结果给学生看。** 阈值 4/6 为默认值，列入 §14 待确认（#13）。

### 11.2 B 类：算法降级（预期内、低频）

**原则：有兜底、有标记。**

| 情况 | 降级动作 |
|---|---|
| 某性别龄组样本 < 30 人，百分位不可靠 | 改用**国标常模**兜底，`percentile_snapshot.source = national`，`stratification_result.percentile_source = national` |
| 模板 `review.status != approved` | 拒绝生成，返回「模板待审校」，教师端提示 |
| 安全替换找不到等价动作 | 不静默跳过；处方状态置 `needs_review`，教师端标记「需人工复核」 |
| 新生无历史体测 | 趋势 = `insufficient_data`，不触发规则 Y4 |

### 11.3 C 类：系统故障（预期外）

**原则：整批回滚、幂等重放。**

- 整批单事务：任一步骤抛未捕获异常 → 回滚，`daily_sync_run.status = failed`，写错误摘要
- 修复后按同一 `(semester_id, business_date)` 重跑，结果一致
- FastAPI 统一异常处理器：业务异常返回结构化错误码，不泄漏堆栈
- 前端 API 失败时显示明确降级提示（「分层数据未更新，当前展示 9 月 15 日结果」）而非白屏——**教师课堂上面对陈旧数据远好于面对空白页**

## 12. 测试策略

与架构分层对齐：

| 目标 | 类型 | 重点 | 覆盖目标 |
|---|---|---|---|
| `domain/` | 纯单元测试 | 7 条分层规则（R1/R2/Y1–Y4/G1）各有独立用例；边界值（W = 1/2/4、体脂率 20.0% / 20.1%）；趋势四标签 + `insufficient_data`；装配器数值正确性；安全替换全条件；预警五规则 | **100% 分支** |
| `domain/` | **黄金用例** | 10–15 个手工构造的典型学生（覆盖各层 × 各短板组合），断言完整链路：原始值 → 国标得分 → 百分位 → 短板 → 标签 → 模板 → 训练包 | 逐人可追溯回归网 |
| `pipeline/` | 集成测试 | 幂等性（同批次跑两次结果一致）；脏数据清洗后计数正确；处方重生成五触发条件；`valid_count < 4` 不分层 | — |
| `adapters/` | 契约测试 | 同一组契约测试同时跑 `MockLePaoAdapter` 与 `HttpLePaoAdapter`，保证未来换真实接口时上层不动 | 两实现全通过 |
| `api/` | 接口 + 性能 | 关键端点与错误码；**单人处方 p95 < 3s、500 人批量 < 60s** | — |
| `seed/` | **数据质量断言** | 分层分布落在目标 ±5%；三层皆非空；**每级预警至少被触发 N 次**；脏数据注入比例符合配置；两学年体测齐备 | 全项通过 |
| `frontend/` | 组件测试（Vitest） | 环形进度条、雷达图、分层可解释性展开的数据映射 | 关键组件 |

两类需单独强调：

**`seed` 的数据质量断言**最易被跳过却最致命——若 500 人里一次红色预警都触发不了，演示时闭环就是断的，而这个问题只有断言能提前抓到。

**黄金用例**是研究项目特有的需求。专家改一次阈值，必须立刻知道哪些学生的分层变了、为什么变。它既是回归网，也是论文中「算法可复现」的直接证据。

## 13. 运行方式

```bash
# 后端
cd backend
python -m venv .venv && .venv\Scripts\activate
pip install -e ".[dev]"

# 1. 生成仿真数据（可复现）
python -m app.seed.generate --students 500 --weeks 16 --seed 20250828

# 2. 一键回放整学期（把所有派生数据、预警、周报一次算完）
python -m app.pipeline.backfill --semester 2025-2026-1

# 3. 或手动跑单日
python -m app.pipeline.daily --semester 2025-2026-1 --date 2025-09-15

# 4. 启动 API
uvicorn app.main:app --reload --port 8000

# 前端
cd frontend
npm install && npm run dev
#   http://localhost:5173/m/        学生端 H5
#   http://localhost:5173/screen/   教师大屏
```

`backfill` 是原型的关键能力：演示时不需要等待逐日累积。

**登录**：预置账号 + 角色切换器（学生 / 教师 / 管理员各若干），不做注册流程。

| 10 | 「二次小测提升」阈值 | 任一指标改善 ≥ 3%（与下降 5% 刻意不对称） | §8.2 | 绿色激励触发率 |

| 14 | HRmax 估算公式 | Tanaka `208 − 0.7 × 年龄`（可切换为 `220 − 年龄`） | §7.3 | 目标心率区间 |

| 16 | 骨骼肌指数是否参与体成分异常判定 | 第一批不参与（入库但不判定） | §6.3 | C 的判定 |
| 17 | 分层可解释性展开是否做 | 做（学生端「我的数据」页） | §9.2 | 前端工作量 |
| **18** | **「8 项」的口径：短板判定基数是 8、7 还是 6** | **8 项原始测量 → 7 个国标计分项（身高体重合成 BMI）→ 6 个短板判定项（排除 BMI，避免与体成分 `C` 重复计数）。指导文件「≥2 项 8 项短板」「8 项全达标」一律按 6 项解读** | **§4.2** | **分层引擎全部规则阈值、R1/R2/Y3 触发率、分层分布** |
| **19** | **国标单项得分的查表口径：就低取档 还是 线性插值** | **就低取档（阶梯查表），与国标官方口径一致，不做插值。理由：插值会产出国标评分表里不存在的分数（实测立定跳远 210cm → 61 分，官方为 60 分；1000 米 280s → 56 分，官方为 50 分），使系统单项分与学校官方体测报表无法逐格对账，而 §12 黄金用例与 §1.3 可追溯性正依赖对账** | **§4.0** | **全部单项得分、国标总分、校内百分位、短板判定；若改用插值须在本 spec 与数据溯源文档明写「与官方报表存在最多 +6 分系统性偏差」** |
| **20** | **国标分组维度：年级组 还是 年龄段** | **官方大学评分表按年级组（大一、大二 / 大三、大四）而非年龄段组织。`AGE_GROUPS` 采用官方年级组名，`age_group_of(age)` 按典型在校年龄 ≤19 / ≥20 折算，属工程约定而非国标条文** | **§4.0、§4.2** | **百分位分组维度「同龄组」的实际含义；若按真实年级分组更准确，需改为从学籍取年级而非按年龄折算** |
| **21** | **离散得分下 P25 的比较符：`<` 还是 `<=`** | **严格 `<`（spec §6.3 原文「低于 P25」）。但须注意：就低取档使每项得分只有 ≤20 个离散取值（男引体向上仅 15 个），P25 处并列质量很高——若某项有 30% 学生同为 60 分且 P25 = 60，则 `<` 只把低于 60 分者判为短板，`<=` 会把这 30% 全判为短板。两者会实质改变 `W`、改变红黄绿比例，甚至改变 `valid_count ≥ 4` 闸门的通过情况** | **§6.3** | **短板判定、分层分布、红色层规模；建议项目组用真实体测数据算一次两种口径下的分层分布再定** |
